# PROJECT_RULES.md — Правила разработки M-Glass App

> Этот файл читается при каждой сессии Claude. Правила нельзя нарушать.

---

## Главное правило на будущее

**CFO Center — единственный источник финансовой правды.**

- Все финансовые данные (маржа, прибыль, себестоимость, налоги, ДДС, P&L) живут ТОЛЬКО в `/cfo/`
- CEO видит только стратегические метрики — без детализации по расчётам
- Никакие финансовые блоки НЕ добавляются в `/admin/`, `/ceo/`, `/commercial/` без согласования с владельцем
- Если нужно добавить финансовый показатель — сначала проверь, нет ли его уже в `/cfo/`

---

## Финансовая модель (формула)

```
Цена клиенту = Себестоимость / (1 − маржа% − налог%)
```

- Налог: **12%** для всех продуктов (mirror, mirror_light, loft, shower, shower_standard, shower_budget)
- Маржа по умолчанию: задаётся в `financial_settings` таблице Supabase
- Накладные расходы уже заложены в маржу — не добавлять отдельной строкой

---

## AmoCRM — только чтение

- Ни одного POST/PATCH/DELETE к AmoCRM API
- Звонки (SIPUNI): notes с `note_type=call_out/call_in` и `params.duration > 0`
- Сообщения (Wazzup): notes с `note_type=call_out/call_in` и `params.duration` отсутствует/0, или `note_type=amomail_message`

## Разделение ролей и маршрутов

| Раздел | Маршрут | Кто видит |
|--------|---------|-----------|
| Менеджер | `/manager` | manager, admin |
| Admin | `/admin` | admin |
| CEO | `/ceo` | ceo, admin |
| CFO | `/cfo` | cfo, ceo, admin |
| Коммерческий | `/commercial` | commercial, admin |

- Один раздел = один маршрут. Логику разделов не смешивать.
- Доступ проверяется в `layout.tsx` каждого раздела через `getRole()`

## Воронка AmoCRM — зоны (стандарт)

| Зона | Этапы |
|------|-------|
| 1 — Квалификация | Получена новая заявка, Назначен ответственный, Проработка, Разговор состоялся, Долгострой, Готов купить |
| 2 — Продажа | Замер назначен, Замер проведён, Согласование, Чертежи в работу, КП отправлено, Счёт выставлен |
| 3 — Производство | Оплата сделана, Счёт оплачен, Заказ в работе, Готово к монтажу, Монтаж, Рекламация, Оплата остатка |

Не изменять зоны без обновления SYSTEM.md и salesMonitor.ts.

## Данные менеджеров

- Менеджер видит только свои сделки (по умолчанию)
- Поле `users.can_view_all_deals: boolean` — расширенный доступ
- Данные одного менеджера НЕ показываются другому без явного разрешения Admin

---

## Суpabase

- `calculations` — все расчёты КП, содержит `cost_breakdown` (JSON) и `financial_breakdown` (JSON)
- `financial_settings` — параметры ценообразования по типу продукта (margin, tax, min_margin)
- `users` / `telegram_users` — пользователи и роли системы

---

## Next.js

- Server Components для страниц с fetch-данными (нет интерактивности)
- Client Components (`'use client'`) для страниц с фильтрами, стейтом, кликами
- Supabase service role key только на сервере — никогда в клиентских компонентах
- Supabase browser client (`createClient` из `lib/supabase-browser`) только в клиентских компонентах

---

## Стиль кода

- Комментарии только если WHY не очевиден
- Никаких docstrings и многострочных комментарий-блоков
- Tailwind-классы инлайн, без CSS-файлов
- Цветовая палитра: `#111110` (text), `#f5f5f3` (bg), `#e4e4e0` (border), `#9a9a95` (muted)
- Маржа: красный < 25%, янтарный 25–35%, зелёный ≥ 35%
