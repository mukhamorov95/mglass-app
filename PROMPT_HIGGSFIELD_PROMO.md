# ТЗ: раздел «💲 Продвижение» — Higgsfield-производство контента и SEO

**Проект:** mglass-app (Next.js 16, React 19, Supabase, TypeScript, Tailwind)
**Доступ:** только владелец (`admin` / `ceo`). Сотрудники раздел не видят.
**Статус документа:** ТЗ на реализацию. Дата: 2026-09-03.

---

## 1. Зачем это

MGlass продаёт душевые перегородки, зеркала с подсветкой, лофт-конструкции.
Это товар, который **продаётся глазами**: клиент должен увидеть блик на стекле,
свет за зеркалом, чистый шов. Значит рост идёт через визуальный контент —
рилсы, обложки, карточки товара, SEO-страницы с реальными изображениями.

Узкое место — не идеи, а **производство**: снять, отрисовать, смонтировать.
Higgsfield закрывает именно это: он генерит кадры, анимирует их, озвучивает,
режет и вшивает субтитры.

Цель раздела — собрать весь маркетинговый конвейер в одном месте, где
владелец нажимает кнопки, а не вспоминает, в каком чате лежал промпт.

## 2. Что умеет Higgsfield (инвентарь)

Higgsfield подключён как MCP-сервер. Он даёт два слоя.

### 2.1 Готовые workflow (сценарии-оркестраторы)

Каждый — это полноценный производственный процесс, а не одна кнопка.
Релевантные для MGlass:

| Workflow | Что делает | Где применить в MGlass |
|---|---|---|
| `product-photoshoot` | Студийные packshot'ы, лайфстайл-сцены, hero-баннеры, карусели, каталожные фото | Зеркала с подсветкой и душевые **без реальной фотосессии** — главный выигрыш |
| `faceless-video` | Многосценовое видео с диктором: скрипт, единый стиль, один голос, вшитые субтитры | Объяснялки: «как выбрать душевую», «чем отличается закалённое стекло» |
| `ugc-product-video` | UGC-ролик, где герой — товар, без спикера в кадре | Рилсы по товару в ленту |
| `ugc-review-video` | Talking-head UGC: человек в кадре рассказывает о товаре | Отзывы, «разбор от мастера» |
| `ugc-tutorial-video` | Пошаговый how-to с подписями «Шаг N» в кадре | «Как ухаживать за стеклом», «как замерить проём» |
| `thumbnail-generation` | Обложки YouTube/Instagram: 16 фреймворков, 4K, лок лица | Обложки к рилсам и статьям |
| `subtitles` | Вшивание субтитров в пиксели по таймингу Whisper | Обязательно для всех рилсов |
| `video-editing` | Монтаж как файл-проект higgsedit: таймлайн, титры, кинетическая типографика, split-screen, LUT, рендер в MP4 | Сборка финального ролика |
| `narrator` | Дикторские дубли под фиксированные окна, длинная начитка в залоченном голосе | Озвучка объяснялок |
| `brand-asset-creation` | Логотипы, айдентика, мокапы, соцграфика, баннеры | Единый визуальный стиль |
| `character-sheet` | Консистентный персонаж в разных ракурсах | Если заводим маскота/постоянного «мастера» |
| `ad-multiplier` | Из одного ролика 4–30 сек — много вариантов с заменой людей/товара | A/B-тесты креативов |

### 2.2 Отдельные инструменты

- **Генерация:** `generate_image`, `generate_video`, `generate_audio`, `generate_3d` (+ батчи)
- **Голос:** `create_voice` (клон), `list_voices`, `voice_change`, `dubbing`
- **Движение:** `motion_control`, `animation_actions`, пресеты image-to-video (`presets_show`)
- **Пост-обработка:** `upscale_image`, `upscale_video`, `remove_background`, `outpaint_image`, `reframe` (переформат под 9:16 / 1:1 / 16:9)
- **Короткие формы:** `shorts_studio_*`, `personal_clipper_*` (нарезка длинного в шортсы)
- **Аналитика:** `virality_predictor`, `video_analysis_*`
- **Публикация:** `tiktok_connect`, `tiktok_music_trending`, `tiktok_prepare_publish`, `tiktok_publish`
- **Медиа:** `media_upload`, `media_import_url` — загрузка своих фото/видео как референсов
- **Биллинг:** `balance`, `show_plans_and_credits`

### 2.3 Чего Higgsfield НЕ делает

- Не режет твоё телефонное видео локально — для этого нужен `ffmpeg` (**сейчас не установлен**)
- Не пишет SEO-тексты и не работает с семантикой — это остаётся на AI-маркетологе проекта
- Не публикует в VK / Instagram / Telegram — только TikTok

## 3. Что в проекте УЖЕ есть (не дублировать!)

Критично: половина конвейера написана. ТЗ **достраивает**, а не пересоздаёт.

| Есть | Файл | Что делает |
|---|---|---|
| Группа меню `MARKETING_CENTER` | `components/Sidebar.tsx` (~стр. 396–405) | Контент-план, AI Video Factory, Медиабиблиотека, Дневной план AI, Партнёры, Акции, Задачи, AI-маркетолог, SEO·Заявки сайта |
| **AI Video Factory** | `app/marketing/video-factory/page.tsx` (927 стр.) | Генерит готовый сценарий: `title`, `hook`, `structure[{time,label,visual,audio}]`, `narrator_text`, **`shots[{order,description,tip}]`**, `b_roll[]`, `editing_notes`, `subtitle_moments[]`, `cta`, `cover_idea`, `telegram_post`, `b2b_version`. Статусы: `idea → script → filming → editing → published` |
| Промпт-генератор | `lib/contentGeneratorPrompt.ts` | `buildContentGeneratorPrompt()`, тип `GeneratedScript` |
| Хранилище сценариев | `app/api/video-studio/{script,save}/route.ts` | Сценарии — файлы `content/video/*.json`, гейт `requireOwner()` |
| Медиабиблиотека | `app/marketing/media-library/page.tsx` | Хранение медиа |
| Owner-гейт | `lib/apiAuth.ts` | `requireOwner()`, `isOwnerRole()` → `admin / ceo` |

**Главный вывод:** `shots[]` из Video Factory — это готовая раскадровка.
Её надо просто **скормить в Higgsfield** как промпты для `generate_image`,
а полученные кадры оживить через `generate_video`. Это и есть недостающее звено.

### 4.2 Страницы

Все под `app/marketing/promo/`, каждая — server component с гейтом владельца
(редирект `/` для остальных ролей, по образцу `app/cfo/layout.tsx`).
Проще всего — один `app/marketing/promo/layout.tsx` с проверкой роли.

| Маршрут | Содержание |
|---|---|
| `/marketing/promo` | **Пульт.** Баланс кредитов Higgsfield, сколько роликов в работе по статусам, что «застряло», кнопки быстрого старта |
| `/marketing/promo/studio` | **Студия.** Выбор workflow (список из §2.1) → форма брифа → запуск → лог задач → превью результата |
| `/marketing/promo/pipeline` | **Конвейер.** Канбан `идея → сценарий → кадры → анимация → монтаж → субтитры → опубликован`. Тянет сценарии из Video Factory, добавляет колонки генерации |
| `/marketing/promo/seo` | **SEO-производство.** Связка «страница сайта → нужные изображения → сгенерировать через `product-photoshoot` → положить в медиабиблиотеку» |
| `/marketing/promo/publish` | **Публикация.** TikTok-аккаунты, подбор трендового звука, предпросмотр публикации, статус |
| `/marketing/promo/budget` | **Бюджет.** `balance`, история трат, прогноз «на сколько роликов хватит» |
| `/marketing/promo/guide` | **Регламент** (см. §5), статическая страница по образцу `app/admin/guide/page.tsx` |

### 4.3 API

Под `app/api/marketing/promo/`, **каждый роут начинается с `requireOwner()`**.

- `POST /api/marketing/promo/generate` — запуск workflow, возвращает `job_id`
- `GET  /api/marketing/promo/status` — опрос задач
- `GET  /api/marketing/promo/balance` — кредиты (кэш 60 сек, чтобы не долбить)
- `POST /api/marketing/promo/from-script` — **ключевой**: берёт `GeneratedScript`,
  разворачивает `shots[]` в промпты изображений, `structure[]` — в тайминги,
  `narrator_text` — в озвучку, `subtitle_moments[]` — в задание на субтитры

### 4.4 Связка с Video Factory

В `app/marketing/video-factory/page.tsx` на карточке сценария добавить кнопку
**«→ В производство»**: шлёт сценарий в `/api/marketing/promo/from-script`
и переводит статус `script → filming`.

Это шов между тем, что уже написано, и новым разделом. Без него раздел —
отдельная игрушка, а не конвейер.

## 5. Регламент работы (содержимое страницы `/guide`)

### Шаг 0. Проверка ресурсов
Открыть «Бюджет и кредиты». Если кредитов меньше порога — пополнить,
иначе генерация упадёт на первом кадре. Норма расхода фиксируется здесь же
после первых 10 роликов.

### Шаг 1. Идея
Идея приходит из «Дневного плана AI» или заводится руками в конвейере.
Одна идея = одна карточка. Без карточки работа не начинается.

### Шаг 2. Сценарий
Генерится в AI Video Factory. Владелец **обязан вычитать** `hook` и `cta` —
это два места, где AI чаще всего промахивается по тону.
Готово → статус `script`.

### Шаг 3. Кадры
Кнопка «→ В производство». `shots[]` уходят в `generate_image`.
Для товара — workflow `product-photoshoot`, для абстрактных сцен — прямая генерация.
Референсы своих реальных изделий грузить через `media_import_url` —
так стекло получается похожим на наше, а не на стоковое.
Брак перегенерить точечно, не весь набор.

### Шаг 4. Анимация
Отобранные кадры → `generate_video` (image-to-video) с пресетом движения.
Правило: движение медленное. Стекло и зеркало плохо переносят резкие панорамы —
появляются артефакты на бликах.

### Шаг 5. Озвучка
`narrator_text` → `generate_audio`. Голос выбирается **один раз** и фиксируется
в регламенте — узнаваемость канала важнее разнообразия.

### Шаг 6. Монтаж
Workflow `video-editing`. Собирает кадры, озвучку, титры по `editing_notes`.
Своё телефонное видео подмешивается здесь же — **требуется `ffmpeg`**.

### Шаг 7. Субтитры
Workflow `subtitles`. Не пропускать: без субтитров рилс теряет досмотры.

### Шаг 8. Обложка
`thumbnail-generation` на основе `cover_idea` из сценария.

### Шаг 9. Проверка
`virality_predictor` до публикации. Низкая оценка — вернуться к шагу 2
и переписать хук, а не публиковать «как есть».

### Шаг 10. Публикация
TikTok — через `tiktok_publish` с трендовым звуком.
Остальные площадки — выгрузка файла и ручная заливка.
Ссылка и метрики заносятся в карточку: `views_count`, `leads_count`, `saves_count`.

### Шаг 11. Разбор
Раз в неделю: какие хуки дали заявки. Победившие формулировки
возвращаются в `lib/contentGeneratorPrompt.ts` — так генератор умнеет.
