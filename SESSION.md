## Контекст
Остаток НЕ редактируется руками — только движением. Списание по заказу всегда с предпросмотром
и по кнопке, автосписания нет сознательно. Непонятые строки BOM привязываются к позиции прямо
в предпросмотре (уходит в `bom_aliases`) — дальше заказ узнаётся сам.
Себестоимость (`avg_cost`, стоимость запаса) видят только admin/ceo/buyer/cfo, остальным API
обнуляет поля.

## Признак происхождения движения (ветка claude/inventory-move-origin)
- Миграция inventory_moves.origin 'fact'|'plan' (ПРИМЕНЕНА), дефолт fact, индекс на plan
- origin протянут через NewMove/addMoves/applyConsume/listMoves; applyConsume(...,'plan')
- POST /api/inventory/consume: origin в теле; «уже списано»/«нечего списывать» → 200 (не 409),
  флаги alreadyConsumed — под автосписание из цеха (не мигать сбоем в логах)
- Журнал помечает plan-движения бейджем «по плану»; панель супервайзера = fact (исправление)
- Требование backbone: автосписание пишет ПЛАН, а не факт → помечено, инвентаризация видит расхождение
- Автосписание дальше пометки НЕ реализую до ответа владельца (разово/партиями)

## Стыковка с производством (production-tab-analysis-739b51-0a)
- Точка вызова: переход флага packaged в mirrorOrderStages (не каждый вызов), packaging всегда последний
- Контракт финал: POST /api/inventory/consume { type:'b2b_order', id, origin:'plan' }, best-effort, 200 на пустом/повторе
- Открыто (к backbone): (a) ~270 старых заказов без задач — историю не догоняем; (б) packaged руками из /b2b-orders мимо цеха — точка вкладки b2b-orders; (в) «на руках» завышен на цикл (резка↔упаковка ~10 сут) — доступный остаток верен, вопрос точности к владельцу
- Производство сначала чинит гонку notes (атомарный mark_order_stages), потом вешает вызов; П19 последняя волна
