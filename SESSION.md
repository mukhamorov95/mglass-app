## Текущая задача
Логика просчёта лестничных (и прямых) стеклянных ограждений: пролёт + ступени → заготовки стекла → расход листа.

## Что сделано (эта сессия)
- lib/railingCalculator.ts (новый) → геометрия наклонного полотна (параллелограмм: нетто = ширина×высота; заготовка = ширина×(высота+ширина·tgθ)), деление пролёта на полотна по maxPanelWidth, слоуп из ступени, погонаж по скату, удельные коэффициенты «на пог.м». Расход листа считает существующий computeMaterialUsage (lib/materialUsage.ts) по прямоугольным заготовкам.
- __tests__/calculators/railingCalculator.test.ts (новый) → 4 теста зелёные, печатает разбивку по объекту (6 пролётов).
- Прогон на реальном объекте (ступень 297/180, H=1000, 10мм, точки, полотно ≤1200, лист 3210×2250): 6 пролётов, погонаж 16.77 м гориз / 19.61 м по скату, нетто 16.79 м², заготовки 26.86 м², обрез ската 10.07 м², ~5 листов, себест. ~137 тыс ₽.

## Следующий шаг (ждёт решения владельца)
Обрез ската даёт ~60% сверх нетто, потому что каждый параллелограмм кроится из своего прямоугольника БЕЗ вложения. В реале наклонные полотна складывают в полосы по скату (общая кромка) — обрез падает вдвое-втрое. Нужно подтверждение владельца, что так и режут, тогда добавить вложение (стек одинаковых полотен в один прямоугольник w×(k·H+w·tgθ)) перед подачей в оптимизатор.
