# ai/ — Операционный слой AI-агентов M-Glass

Эта папка содержит **декларативный AI-слой** — описания агентов, навыков, инструментов, сценариев и политик безопасности для бизнеса M-Glass.

> **Важно:** Папка `ai/` не изменяет бизнес-логику приложения. Она добавляет слой поверх существующего кода — агенты читают данные через разрешённые инструменты, но не меняют формулы, не запускают миграции и не отправляют ничего клиентам без подтверждения человека.

---

## Структура

```
ai/
├── README.md                  ← этот файл
├── agents/                    ← роли AI-агентов
├── skills/                    ← рабочие процедуры (что и как делать)
├── tools/                     ← реестр разрешённых инструментов
├── workflows/                 ← сценарии работы (когда и кто)
├── memory/                    ← долгосрочные правила бизнеса
└── policies/                  ← ограничения и безопасность
```

---

## Слои и их назначение

### `agents/` — Роли

Агент = роль с определёнными обязанностями, навыками и ограничениями. Агент не делает ничего за рамками своей роли. Каждый агент знает:
- за что он отвечает
- какие skills может вызывать
- какие данные может читать
- что требует подтверждения Владислава
- что запрещено полностью

Текущие агенты:
| Агент | Роль |
|---|---|
| `chief-of-staff-agent` | Координация, утренние и вечерние брифинги |
| `sales-director-agent` | Мониторинг менеджеров, анализ воронки |
| `proposal-engineer-agent` | Подготовка и проверка КП |
| `production-dispatcher-agent` | Контроль готовности к запуску в производство |
| `finance-controller-agent` | Проверка маржи, финансовых показателей |

---

### `skills/` — Рабочие процедуры

Skill = конкретная задача с пошаговым алгоритмом. Skill не принимает решений — он собирает данные, делает расчёты через TypeScript-калькуляторы и возвращает структурированный результат.

Текущие skills:
| Skill | Назначение |
|---|---|
| `create-commercial-proposal` | Подготовка черновика КП |
| `check-catalog-item` | Проверка позиции в справочнике фурнитуры |
| `check-order-before-production` | Проверка готовности заказа к производству |
| `analyze-crm-day` | Анализ активности менеджеров за день |
| `generate-production-plan` | Формирование плана производства |
| `check-margin` | Проверка маржинальности сделки |
| `audit-manager-work` | Аудит работы менеджера за период |

---

### `tools/` — Инструменты

Реестр разрешённых операций с данными. Каждый инструмент описан декларативно: что читает, что возвращает, какой уровень разрешения требует. Реальные вызовы идут через типизированный `tool-registry.ts`.

**Принцип:** инструменты — это не прямой доступ к Supabase или AmoCRM, а обёртки с явными разрешениями.

---

### `workflows/` — Сценарии

Workflow = описание того, когда и что происходит. Это не код — это регламент. Агенты следуют workflows как инструкции. Каждый workflow указывает, в какой точке требуется подтверждение человека.

---

### `memory/` — Долгосрочные правила

Стабильные факты о бизнесе M-Glass, которые не меняются от сессии к сессии:
- продуктовая линейка
- правила ценообразования
- правила работы с сотрудниками
- правила производства

Агенты читают `memory/` перед принятием любых решений.

---

### `policies/` — Политики безопасности

Обязательные ограничения на любое действие агента. Если действие не разрешено политикой — агент не выполняет его, даже если технически может.

Три документа:
- `ai-safety-policy.md` — что AI никогда не делает
- `approval-policy.md` — уровни действий и кто что может
- `permissions-policy.md` — матрица прав по агентам

---

## Принципы

1. **AI не заменяет решение человека** — только готовит информацию и черновики.
2. **Точные расчёты — только TypeScript.** Языковая модель не считает цены.
3. **AmoCRM — только чтение.** Никаких изменений в CRM.
4. **Каждое действие логируется** через `writeAgentLog`.
5. **Подтверждение Владислава** требуется для любого действия с деньгами, клиентами или производством.
