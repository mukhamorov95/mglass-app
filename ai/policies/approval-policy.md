# approval-policy.md — Политика подтверждений

> Описывает уровни действий агентов: что можно автономно, что требует подтверждения, что запрещено.

---

## Уровни действий

| Уровень | Код | Описание |
|---|---|---|
| Только чтение | `read_only` | Агент читает данные. Никаких изменений. |
| Черновик | `draft` | Агент создаёт черновик. Не сохраняется и не отправляется. |
| Предложение | `suggest` | Агент предлагает действие. Человек решает. |
| Требует подтверждения | `approve_required` | Агент подготовил, но ждёт явного approve Владислава. |
| Выполнение | `execute` | Действие выполняется. Только при явном разрешении агента. |
| Административный | `admin` | Системные операции. Только вручную Владиславом. |

---

## Что агент может делать автономно (read_only / draft)

Агенты могут выполнять следующее **без подтверждения**:

- Читать сделки из AmoCRM (GET-запросы)
- Читать расчёты и КП из Supabase (`calculations`, `order_groups`)
- Читать справочники фурнитуры и материалов
- Читать `financial_settings` для проверки маржи
- Анализировать активность менеджеров за день
- Формировать черновики КП (не отправлять)
- Формировать текстовые отчёты (не отправлять)
- Проверять маржу расчёта
- Готовить список вопросов для согласования
- Логировать все свои действия через `writeAgentLog`

---

## Что требует подтверждения Владислава (approve_required)

Следующие действия **не выполняются** без явного `approve` от Владислава:

| Действие | Почему |
|---|---|
| Отправить КП клиенту | Коммерческое обязательство |
| Изменить цену или скидку | Влияет на маржу |
| Запустить заказ в производство | Необратимое действие |
| Назвать клиенту срок | Обязательство по времени |
| Создать счёт | Финансовый документ |
| Изменить состав заказа | Может затронуть производство |
| Отклонить заказ | Потеря клиента |
| Выдать расширенный доступ менеджеру | Управление данными |

---

## Что запрещено полностью (admin only / NEVER)

| Действие | Причина запрета |
|---|---|
| Изменять данные в AmoCRM | AmoCRM — только чтение |
| Удалять расчёты или сделки | Необратимо |
| Изменять формулы калькуляторов | Нарушает финансовую модель |
| Изменять роли пользователей | Управление безопасностью |
| Запускать миграции БД | Необратимо |
| Обращаться к .env или секретам | Безопасность |
| Отправлять что-либо от имени менеджера | Нарушение ответственности |

## Матрица действий по агентам

| Агент | read_only | draft | suggest | approve_required | execute |
|---|---|---|---|---|---|
| chief-of-staff | ✅ | ✅ отчёты | ✅ | запрашивает у Владислава | ❌ |
| sales-director | ✅ | ✅ отчёты | ✅ рекомендации | запрашивает у Владислава | ❌ |
| proposal-engineer | ✅ | ✅ КП | ✅ | запрашивает у менеджера | ❌ |
| production-dispatcher | ✅ | ✅ планы | ✅ | запрашивает у Владислава | ❌ |
| finance-controller | ✅ | ✅ отчёты | ✅ | запрашивает у Владислава | ❌ |

> Ни один агент не имеет уровня `execute` в текущей конфигурации этапа 1.
> `execute` будет активирован только после полного аудита и явного решения Владислава.

## Процедура запроса подтверждения

Когда агент достигает точки `approve_required`:

1. Агент останавливается
2. Формирует краткое summary: что сделано, что ждёт подтверждения, возможные риски
3. Выводит: `[ОЖИДАЕТ ПОДТВЕРЖДЕНИЯ ВЛАДИСЛАВА]`
4. Логирует ожидание через `writeAgentLog` со статусом `pending_approval`
5. Не продолжает до получения явного ответа `approve` или `reject`

При `reject` — агент логирует отказ и архивирует черновик без удаления данных.
