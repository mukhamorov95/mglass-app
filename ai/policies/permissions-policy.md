# permissions-policy.md — Матрица прав доступа агентов

> Определяет, какие данные каждый агент может читать, какие инструменты использовать, и к каким разделам приложения он имеет доступ.

---

## Принципы

1. **Минимальные привилегии** — агент получает доступ только к тому, что нужно для его роли.
2. **Явное разрешение** — если разрешения нет в этом документе, действие запрещено.
3. **Изоляция данных менеджеров** — агент не передаёт данные одного менеджера другому.
4. **Аудит каждого действия** — все операции логируются через `writeAgentLog`.

---

## Доступ к данным по агентам

### `chief-of-staff`

| Данные | Уровень |
|---|---|
| Сделки AmoCRM (все менеджеры, агрегировано) | read_only |
| Расчёты Supabase (все) | read_only |
| Активность менеджеров (AmoCRM Notes) | read_only |
| financial_settings | read_only |
| agent_logs | read_only + write (только свои логи) |

Запрещено: данные отдельного менеджера для показа другому; изменение данных.

---

### `sales-director`

| Данные | Уровень |
|---|---|
| Сделки AmoCRM (все менеджеры) | read_only |
| Активность менеджеров (звонки, сообщения) | read_only |
| Расчёты и КП (все менеджеры) | read_only |
| Воронка по зонам (зоны 1–3) | read_only |
| agent_logs | read_only + write (только свои логи) |

Запрещено: изменение данных CRM; удаление КП; изменение ролей.

---

### `proposal-engineer`

| Данные | Уровень |
|---|---|
| Справочник фурнитуры (shower_catalog_items) | read_only |
| Справочник материалов и услуг | read_only |
| Расчёты по конкретной сделке | read_only |
| financial_settings (маржа, налог) | read_only |
| Черновик КП | draft (создать, не отправить) |
| agent_logs | write (только свои логи) |

Запрещено: отправка КП клиенту; изменение цен; изменение формул калькулятора.

---

### `production-dispatcher`

| Данные | Уровень |
|---|---|
| Сделки в зоне 3 (Производство) из AmoCRM | read_only |
| Расчёты и состав заказа | read_only |
| Справочник фурнитуры (наличие, сроки) | read_only |
| Черновик производственного плана | draft |
| agent_logs | write (только свои логи) |

Запрещено: изменение статусов сделок; запуск в производство без approve; изменение состава заказа.

---

### `finance-controller`

| Данные | Уровень |
|---|---|
| Расчёты и КП (все) | read_only |
| financial_settings | read_only |
| Сделки с оплатой (зона 2–3) | read_only |
| Маржа по сделкам | read_only |
| Черновик финансового отчёта | draft |
| agent_logs | write (только свои логи) |

Запрещено: изменение цен; изменение financial_settings; удаление расчётов.

---

## Соответствие ролям приложения

| Агент AI | Роль в приложении (SYSTEM.md) |
|---|---|
| `chief-of-staff` | admin-уровень (читает всё, изменяет ничего) |
| `sales-director` | commercial + admin (только чтение) |
| `proposal-engineer` | manager (только свои сделки + справочники) |
| `production-dispatcher` | commercial + admin (только зона 3) |
| `finance-controller` | cfo (только чтение финансовых данных) |

---

## Изоляция данных менеджеров

Правило из SYSTEM.md применяется к агентам без исключений:

- `proposal-engineer` работает только с данными конкретного менеджера, которому помогает
- Агент не может получить сделки менеджера А и передать менеджеру Б
- `chief-of-staff` и `sales-director` видят агрегированные данные — без показа персональных деталей одного менеджера другому
- Все нарушения изоляции данных логируются как `security_violation` в `agent_logs`
