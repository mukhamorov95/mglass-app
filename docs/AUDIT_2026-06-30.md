## P1 — Синхронизация owner → команда
Кеша Next.js на пути чтения нет (всё `'use client'` + живой Supabase). Реальный рассинхрон — «осиротевшие источники правды».

| Что меняет владелец | Пишется | Читается командой | Синхронно |
|---|---|---|---|
| Бонусы (бонус-центр) | `sales_bonuses` | «Мои доходы» → `earnings_settings` (др. таблица) | ❌ |
| Зоны доставки | `delivery_zones.price` | калькуляторы → `pricing_formula` (база+км) | ❌ |
| Скрипты продаж | `sales_scripts` | нет UI команды (только AI-чат) | ❌ |
| Налог 12% | `financial_settings.tax_percent` | `app/cfo/unit/page.tsx:76` и ряд мест — хардкод `12` | ❌/риск |
| Цена закупки | `suppliers` | `materials.cost_price` = разовый снимок | ❌ |
| Цены стекла, формула, маржа, waste, бригады | — | читаются живьём, один источник | ✅ |

- **HIGH** `financial_settings` выбирается по строковому ключу (`mirror_light`, `shower_standard`…); при промахе чтение **молча** откатывается на `standard`/`[0]`/12% без ошибки (UI-калькуляторы не используют `hasExactFinancialSettings`, который есть в `quickCalc.ts:158`).
- **MED** `earnings_settings` редактируется только инлайн в `my-earnings`, у владельца нет отдельного admin-UI.
- **LOW** `glass_price_matrix` поддерживает `t12` в write/loft/shower, но тип `GlassMatrixRow`/`MATRIX_MM` в `lib/glassMatrix.ts` обрывается на `t10` → в зеркальном калькуляторе цены 12 мм нет.

## P1 — Деньги (ценообразование)
Формула `cost / (1 − маржа − налог)` в B2C едина; деления на ноль защищены; **LLM цену не считает**. Но единообразие ломается:
- **HIGH** Двойная маржа на стекле (зеркало `app/calculator/mirror/page.tsx:451`, душевая `app/calculator/shower/page.tsx:160`, quickCalc `lib/quickCalc.ts:129`): в формулу подаётся sale-цена стекла (уже с маржой) и делится повторно. Исправляющий `lib/pricing/calculateMirrorUnified.ts` написан, но **не подключён** к live UI.
- **HIGH** Душевая считается по-разному по каналам: web → `tax_percent` (12%), AI/quickCalc → tier-расходы 33% (budget) / 39% (standard) (`showerCalculator.ts:66,74`). Одна и та же душевая стоит по-разному из веба и из Telegram/AI.
- **MED** `lib/calcServiceCost.ts:69` — услуги через наценку `×(1+markup)`, а не `/(1−margin)` → маржа услуг занижена.
- **MED** Пороги цвета маржи в `lib/ai-tools/b2bQuickQuoteTool.ts:174-178` (green ≥30, red <20) ≠ канон `lib/types.ts:computeMarginStatus` (green ≥35, red <25).

## Отдельный трек — B2B-кабинет для внешних клиентов
Текущий «B2B-контур» — внутренний инструмент сотрудников; изоляция по `created_by` (менеджеру), а не по клиенту/организации. **Пускать внешних клиентов в текущем виде нельзя.**

**P0-фундамент (без него никого не пускать):**
1. Роль `b2b_client` (НЕ в `OWNER_ROLES`) + отдельное дерево `/portal/*`, изолированное от внутренних разделов.
2. Явная привязка `auth.users.id → b2b_clients.id` + RLS по ней (сейчас изоляция по менеджеру).
3. Убрать fail-open `auth.org_id() → 1`; deny-by-default.
4. Добор RLS на B2B-таблицы без org/client-скоупа (`b2b_lead_activities`, `b2b_materials`, `b2b_calculation_attachments`, `b2b_material_sheet_variants`, `b2b_films`, `b2b_catalog_*`) — себестоимость клиенту видна быть не должна.
5. Закрыть `/api/admin/b2b-*` через `requireAdmin`; убрать ветку доступа `created_by===null` в `app/api/quotes/[id]/pdf/route.ts:41`.

**P1-функционал:** мои заказы+статусы (очищенная проекция без себестоимости), мои КП/счета (client-scope), каталог + B2B-калькулятор (переиспользуем `lib/b2bCalculator.ts`), повторный заказ.
**P2:** отдельный provisioning клиента (не `setup-org`, который делает admin), вход/брендинг, аудит действий клиента.

**Переиспользуемые кирпичи:** `lib/b2bCalculator.ts` (цена на сервере, VAT 22%), `b2b-quotes/[id]/kp` + `api/quotes/[id]/pdf`, табло статусов `lib/productionStages.ts`, `createScopedClient`, механизм `B2BScope`.
