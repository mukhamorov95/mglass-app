# Прайсовая система B2B — стекло и зеркало

Слой «прайс поставщика» над справочником «Стекло». Поставщик присылает новый прайс —
Вера загружает файл, система показывает, что изменится в себестоимости, и меняет только
подтверждённое. Все версии прайсов и их файлы хранятся вечно.

## Поток данных

```
файл прайса (PDF/XLSX)
   │  парсинг в браузере (pdfjs / xlsx) → сетка по координатам → секции и колонки
   ▼
glass_price_lists          версия прайса: дата, файл в Storage, статус, кто загрузил
glass_price_list_items     неизменяемый снимок цен этой версии (секция × продукт × толщина)
   │  glass_price_mappings — «строка справочника ← колонка прайса» (+ коэффициент, округление)
   ▼
план изменений (diff)      превью: было → станет, Δ%, маржа до/после
   │  подтверждение вручную
   ▼
glass_price_matrix (price_type='cost')      ← ЕДИНСТВЕННОЕ, куда пишет этот слой
glass_price_apply_log      журнал: какая ячейка, было/стало, из какой версии прайса
   │  существующая кнопка «Синхр. в B2B» (/api/admin/sync-b2b-materials)
   ▼
b2b_materials.cost_price → калькулятор B2B, просчёты, КП, раскрой
```

## Границы (что этот слой НЕ делает)

1. **Не трогает продажные цены.** `price_type='sale'` остаётся за владельцем. Маржа
   показывается справочно (красная < 25%, жёлтая 25–35%).
2. **Не пишет в `b2b_materials`.** Единственная точка входа туда — прежний
   `/api/admin/sync-b2b-materials`. После применения прайса UI предлагает нажать синхронизацию.
3. **Не создаёт и не удаляет строки справочника.** Нет строки — честный `skip: no_matrix_row`.
4. **Не обнуляет цены.** Нет цены на толщину в новом прайсе → ячейка остаётся прежней (`skip: no_price`).
5. **Меняет только ячейки с активной привязкой.** Нет маппинга — колонка прайса просто
   перечислена в «непривязанных».
6. **Ничего не применяет автоматически.** Загрузка = черновик; запись в матрицу — отдельное
   действие человека после просмотра diff.

## Таблицы

| Таблица | Смысл | Кто пишет |
|---|---|---|
| `glass_price_lists` | версия прайса: поставщик, `price_date`, файл (`b2b-attachments/supplier-price/glass/<id>/…`), статус `draft/applied/archived` | API загрузки/применения |
| `glass_price_list_items` | снимок цен версии: `section, product, variant_code, thickness_mm, sheet_format, price_per_m2` | API загрузки |
| `glass_price_mappings` | привязка `matrix_name+matrix_category+thickness → section+product`, `coefficient`, `rounding`, `enabled`. `thickness=0` — правило на все толщины, конкретная толщина перекрывает его | владелец/закупщик |
| `glass_price_apply_log` | журнал применений: ячейка, было/стало, версия прайса, кто и когда | API применения |

RLS: чтение — любому авторизованному сотруднику, запись — только service-role через API
с гейтом `requireRole(['admin','ceo','buyer'])`.

## Маршруты

- `/admin/glass-price-lists` — страница прайсов (кнопка «📄 Прайсы поставщика» в правом
  верхнем углу `/admin/glass-prices`, с датой действующего прайса).
- `GET/POST /api/admin/glass-price-lists` — список версий / загрузка новой (multipart: файл + разобранные строки).
- `GET/PATCH/DELETE /api/admin/glass-price-lists/[id]` — карточка версии; удалить можно только неприменённый черновик.
- `GET /api/admin/glass-price-lists/[id]/file` — подписанная ссылка на оригинал (10 мин).
- `GET/POST /api/admin/glass-price-lists/[id]/plan` — превью изменений / применение.
- `GET/POST/DELETE /api/admin/glass-price-mappings` — привязки (+ автоподбор `?suggest_from=<listId>`).
- `GET /api/admin/glass-price-history` — действующий прайс и история по ячейке
  (`?name=&category=&thickness=`) — «какая цена была, когда действовал прайс от такой-то даты».

## Парсер (`lib/glassPrice/`)

- `extract.ts` — файл → текстовые куски с координатами (pdfjs грузится статикой из `/public`,
  мимо бандлера) или сетка листа xlsx.
- `grid.ts` — куски → строки/ячейки по геометрии: `y` с допуском 3.2 pt — строка, соседние
  спаны ближе 6 pt — одна ячейка.
- `parse.ts` — сетка → таблицы. Колонки собираются кластеризацией по `x`, поэтому пропуск
  («н/д» отсутствует ячейкой) не сдвигает цены в соседний столбец. Поддержаны три формы
  таблиц AIG: матрица «Толщина × продукты», «Толщина + Название/РАЛ + Цена за кв.м.» и
  две таблицы триплекса в одной строке (делятся по колонке с кодами `33.1/33.2`).
- `applyPlan.ts` — чистая функция плана (`buildApplyPlan`) и автоподбор привязок
  (`suggestMappings`): текущая себестоимость пришла из прошлого прайса того же поставщика,
  поэтому совпадение цен по нескольким толщинам однозначно указывает на колонку.

Тесты: `__tests__/glass-price-parse.test.ts` (на реальном файле AIG от 10.02.2026,
фикстура в `__tests__/fixtures/`), `__tests__/glass-price-apply.test.ts`.

## Как работает Вера

1. `/admin/glass-prices` → «📄 Прайсы поставщика».
2. «＋ Загрузить новый прайс» → файл → система показывает распознанные таблицы → дата прайса
   подставляется из файла → «Сохранить версию».
3. Вкладка «Привязки» — один раз проверить/дополнить («Подобрать автоматически» заполняет по
   совпадению цен). Дальше привязки переиспользуются.
4. Вкладка «Что изменится» — diff по ячейкам с Δ% и маржой → «Применить к себестоимости» →
   затем «⟳ Синхронизировать в B2B».
5. Старые версии остаются в списке: «Открыть файл» — оригинальный PDF, «Строки прайса» —
   цены той даты, журнал — что именно эта версия поменяла.
