# Архитектура собственной CRM MGlass (замена AmoCRM)

Цель — заменить AmoCRM собственным контуром `/crm`, сохранив привычные менеджерам сущности и добавив автоматизацию. AmoCRM остаётся **read-only архивом** (лицензия до конца 2026). Ориентир по модели и UX — amoCRM, но без её лишней сложности.

## 1. Что уже есть (база)

| Слой | Реализация |
|---|---|
| Лиды | `crm_leads` (источник, контакты, продукт/размеры/бюджет, этап, скоринг, менеджер, статус won/lost, `est_amount`/`est_profit`) |
| Воронка | `lib/crmStages.ts` — 3 зоны (Квалификация/Продажа/Производство), 23 канонических этапа (SYSTEM.md) |
| Лента событий лида | `crm_lead_events` (kind: system/call/message/note/stage; `meta jsonb`) |
| Каналы входа | Авито (бот «Иван» + импорт), звонки (OnlinePBX/SIPUNI вебхуки), ручной ввод, зеркало AmoCRM (`sync-amo`) |
| Телефония | OnlinePBX: приём событий/записей в ленту + click-to-call из карточки |
| Изоляция | Менеджер видит свои лиды; владелец/CEO/РОП/`can_view_all_deals` — все (в коде, не в RLS) |
| Карточка | `/crm/[id]` — поля, переписка Авито, звонок, лента, смена этапа |

## 2. Что добавлено в этой итерации (PR «CRM amoCRM-style»)

1. **Задачи/напоминания** (`crm_tasks`) — ядро amoCRM: у лида есть следующий шаг с дедлайном (звонок/встреча/замер/напоминание). Просроченные и «на сегодня» — верхняя панель `/crm`; просрочка подсвечивает карточку 🔴; в карточке — блок задач (создать/закрыть). API `/api/crm/tasks` (GET/POST/PATCH), изоляция по исполнителю/менеджеру.
2. **Лента активности** (`/api/crm/activity` + панель на `/crm`) — хронология всех событий за день (звонки/сообщения/этапы/заметки/система) с фильтрами и ссылкой на карточку. Владелец видит всё, менеджер — свои.
3. **Deep-link уведомлений** — Telegram-пинги Авито и звонков ведут на конкретную карточку `/crm/{id}`, а не на общую доску.

## 3. Целевая модель (amoCRM-паритет) — что строить дальше

### 3.1 Сущности
- **Контакты и компании** (`crm_contacts`, `crm_companies`) — сейчас контакт «зашит» в лид. Отдельные справочники: телефон/почта/должность, привязка к лидам many-to-many, дедуп по телефону. Даёт «историю клиента» через все сделки (дизайнеры/прорабы с повторными заказами).
- **Несколько воронок** (`crm_pipelines`) — сейчас одна «Продажи». Добавить B2B-воронку, сервис/рекламации отдельным pipeline.
- **Теги** (`crm_lead_tags`) — быстрая сегментация (горячий, дизайнер, Воронеж, реклама-источник).
- **Кастомные поля** — пока фиксированные колонки; при росте — `crm_field_values` (jsonb на лид) с реестром полей.

### 3.2 Автоматизация (Digital Pipeline / Salesbot)
- **Авто-задача при смене этапа** — правило «этап X → создать задачу типа Y через N часов» (нет задачи после действия — amoCRM это форсирует). Таблица `crm_stage_rules`.
- **SLA/просрочка этапа** — если лид «завис» на этапе дольше нормы (зоны из `salesMonitor`), авто-пинг менеджеру и в ленту владельца. Переиспользовать зоны воронки.
- **Авто-назначение** (round-robin) — новый лид без ответственного распределяется по менеджерам (уже есть `AMOCRM_ROUND_ROBIN_ENABLED` для amo — перенести логику на `crm_leads`).
- **Бот-квалификатор** — уже есть (Иван); расширить на автосоздание задачи «перезвонить» при `needs_human`.

### 3.3 Рабочие представления
- **«Неразобранное»** (unsorted) — новые лиды без ответственного отдельной вкладкой (сейчас это первая колонка «Получена новая заявка»). Кнопка «Взять».
- **Список + канбан** — переключатель «доска/список» с сортировкой (по сумме, дате, просрочке) и фильтрами (менеджер, источник, тег, этап, диапазон дат).
- **Мой день менеджера** — задачи на сегодня + просроченные + новые лиды (частично закрыто панелью задач; свести в `/manager`).
- **Дашборд владельца** — воронка (конверсия по этапам), задачи-просрочка по менеджерам, лента активности (лента уже есть), суммы pipeline. Часть метрик уже в `/commercial` (по amo) — постепенно переключить на `crm_leads`.

### 3.4 Коммуникации (омниканальность)
- **Единый инбокс** — Авито (есть) + WhatsApp/Telegram через Wazzup (нужен ключ) + звонки (есть) в одной ленте карточки. Клиентская переписка и внутренние заметки разделены (есть).
- **Шаблоны сообщений/КП** — быстрые ответы, отправка КП из карточки (kind `quote` в `crm_lead_events` уже зарезервирован).

### 3.5 Отчётность
- Конверсия воронки по этапам и по менеджеру; средний чек; длительность цикла; причины отказов (`lost_reason` уже есть) — агрегаты поверх `crm_leads`/`crm_lead_events`.

## 4. Фазовый план

| Фаза | Содержание | Статус |
|---|---|---|
| **0** | Воронка + карточка + каналы (Авито/звонки/amo-зеркало) | ✅ есть |
| **1** | Задачи/напоминания, лента активности, deep-link уведомлений | ✅ эта итерация |
| **2** | Авто-задача по этапу + SLA-просрочка этапа + «Неразобранное» | ⏳ |
| **3** | Контакты/компании (справочник, история клиента, дедуп) | ⏳ |
| **4** | Теги + фильтры + список/канбан + сортировки | ⏳ |
| **5** | Дашборд владельца на `crm_leads` (конверсия, просрочки, суммы) | ⏳ |
| **6** | Омниканальный инбокс (Wazzup WA/TG) + шаблоны/КП из карточки | ⏳ (нужен ключ Wazzup) |
| **7** | Отключение AmoCRM: перенос активных сделок скриптом, amo → архив | ⏳ (по команде владельца) |

## 5. Принципы
- **Ничего не ломаем**: новые таблицы аддитивны, RLS permissive + изоляция в коде (как `crm_leads`), миграции идемпотентны (`if not exists`).
- **AmoCRM — только чтение** (жёсткое правило проекта).
- **Одна воронка = один канон этапов** (`lib/crmStages.ts`); менять этапы — синхронно с `salesMonitor.ts`.
- **Детерминизм цен** — из калькуляторов, не из LLM (правило проекта).
- Русский UI, палитра проекта, Server/Client разделение как в остальном приложении.
