# Распределение новых заявок — маршрут

Начат 30.09.2026 по просьбе владельца: каждая новая заявка «Продаж» сама получает ответственного —
знакомый клиент своему менеджеру, новая по очереди, перегруженным не даём. Справедливо и без завала.

## Цель

1. Время от заявки до ответственного — минуты вместо медианы 19 мин и хвоста в сутки.
2. Заявок за день у продавцов на смене поровну (разница не больше одной), кроме знакомых клиентов.
3. Перегруженный менеджер не получает новых, пока не разберёт хвост; каждое «пропустили» видно с причиной.

## Алгоритм (одинаков в тени и вживую)

1. **Знакомый клиент.** Контакты сделки (и номер из имени «Пропущенный 7…», если контакта нет) → другие сделки
   контакта → ответственный самой свежей. Продавец и на смене → ему, даже если загружен. Иначе — в очередь
   с пометкой «клиент такого-то».
2. **Кто на смене.** Продавец (`is_seller`), `starts_on` наступил, сейчас его день и часы по графику. Суббота —
   тот, кто уже действовал в amo сегодня (дежурного в графике нет). Через час после начала смены без единого
   действия в amo — «нет на месте», не получает.
3. **Перегруз** (признаки «Моего дня», `lib/coaching/focus.ts`): клиентов ждут ответа ≥ 6, или пропущенных без
   перезвона ≥ 3, или новых заявок без касания ≥ 3 → пропускаем с причиной. Пороги сняты с живой загрузки
   30.09 12:50 (ждут ответа: Яна 3, Айжан 4, Семён 2, Александра 8): при «3» перегружены все на смене и очереди нет.
4. **Справедливость.** Из оставшихся — у кого меньше заявок за сегодня по журналу; при равенстве — кто дольше
   не получал. Перегружены все → наименее загруженный, и сигнал владельцу.
5. **Нерабочее время.** Никого на смене → заявка ждёт; первым прогоном смены делится между вышедшими.

## Этапы

### Р0. Тень — СДЕЛАНО / в работе
Крон `/api/cron/lead-distribution` каждые 5 мин: новые заявки «Продаж» → решение и причина в `lead_distribution`,
в amo ничего. Вечером владельцу: «назначил бы алгоритм» против «назначили вручную», совпадения, скорость.
**Проверка:** тесты правил; прогон по живому amo; три решения сверены с карточками руками.

### Р1. Неделя тени — ждёт Р0
Сравнить по 5 рабочим дням: скорость, равномерность, где алгоритм и люди расходятся и почему. Поправить пороги.

### Р2. Вживую — ждёт решения Д1 после Р1
Смена ответственного у новой сделки + перенос её открытых задач на нового ответственного. Единственная запись,
узкая, за тумблером `live`; сделку, которую человек уже передал сам, не трогаем.

### Р3. Экран «Распределение» — потом
Кто сколько получил, кого пропустили и почему, пороги — владельцу.

## Грабли

- Строгий круг по индексу в одной ячейке ломается при двух одновременных вызовах и отдаёт заявки отсутствующим —
  счёт ведём по журналу решений за день, состав — по графику.
- Вебхук amo без подписи открыт всему интернету — вместо него крон.
- АТС заводит сделку по пропущенному без привязки к контакту — номер берём и из имени сделки.

## Потолок

- Загрузку видим только по следу в amo: разговор с личного телефона мимо amo распределитель не видит.
- Качество менеджера (конверсия) в Р0–Р2 не учитываем — только смена, загрузка и очередь.
