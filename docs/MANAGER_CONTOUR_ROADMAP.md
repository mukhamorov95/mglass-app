## А0 — где мы сейчас (B2B)

**Что работает:**
- Просчёт: `/calculator/b2b` — единый движок `lib/b2b/computeQuote.ts`, авто-надбавки за габариты,
  договорные цены позиций, мин. цена, триплекс, фацет.
- Список просчётов `/b2b-quotes`: фильтры и статусы, PDF-КП, текст для Telegram, КП для печати,
  счёт-спецификация, вложения, честная маржа владельцу, **ручная корректировка итога (сделано 25.08)**.
- Запуск в работу → `/b2b-orders` → раскрой `/b2b-cutting` → `Production App` → статус оплаты.
- Аналитика `/b2b-analytics`, воронка `/b2b-pipeline`, развитие `/b2b-growth`.
- Партнёрский кабинет: заявка партнёра приходит в те же просчёты.

**Что болит (это и есть источник шагов):**
1. Партнёр в своём кабинете умеет больше менеджера: УПД, онлайн-оплата, повтор заказа, честный срок.
2. «B2B Клиенты» менеджеру не открывается — карточки клиента у него фактически нет.
3. Просчёт и заказ — два списка; шов лечится вкладкой «Требуют переноса» и плашкой «Похоже, это уже заказ».
4. Скидка клиента — одна цифра на всё; индивидуальных цен по материалам нет.
5. Отправка клиенту — руками: скачал PDF, скопировал текст, вставил в Telegram.
6. Нет экрана «мой день по B2B»; нет уведомлений менеджеру о событиях его заказов.
7. Срок отгрузки в просчёте — договорной по умолчанию, не из загрузки производства.
8. Остатки склада в просчёте не видны (складской контур есть, в меню менеджера его нет).

## М0 — где мы сейчас (MGlass / B2C)

**Что работает:** заявки и воронка из AmoCRM (`/manager`, `/crm`, read-only), калькуляторы
(быстрый расчёт, зеркало, душевая, лофт, ограждение, 3D-визуализатор, скан дизайн-проекта),
корзина мультизаказа, КП (PDF), договор/счёт (`/contracts`), история расчётов, заказы, клиенты,
календарь, заявки на замер и форма замера, монтажи, «мои заработки».

**Что болит:** поток разнесён по разным экранам (заявка → замер → расчёт → КП → договор → монтаж —
это пять разных мест); замер не перетекает в расчёт; онлайн-оплаты и клиентского кабинета нет;
закрывающих документов по монтажу (акт, фото) нет.

## B2C: М1 → М20

### Фаза 1. Собрать поток в одну карточку (М1–М6)
- **М1.** Единая карточка сделки B2C: заявка → замер → расчёт → КП → договор → оплата → производство → монтаж → акт.
- **М2.** Замер втекает в расчёт: размеры из формы замерщика подставляются в калькулятор без переписывания.
- **М3.** Заявка на замер из карточки в один клик + слоты в календаре замеров.
- **М4.** КП с визуалом: картинка из 3D-конфигуратора / скана дизайн-проекта прямо в КП.
- **М5.** Согласование КП клиентом по ссылке (общий механизм с А5).
- **М6.** Договор автозаполнением из расчёта + подпись по ссылке.

### Фаза 2. Деньги (М7–М11)
- **М7.** Онлайн-оплата B2C (общий провайдер с А8): аванс по ссылке из КП.
- **М8.** Аванс/остаток и напоминание об остатке перед монтажом.
- **М9.** Себестоимость по факту: замер vs факт монтажа, реальная маржа сделки.
- **М10.** План/факт менеджера и прозрачный бонус (`/my-earnings` + `month_plans`).
- **М11.** Допродажи: подсветка «к этому обычно берут» прямо в расчёте.

### Фаза 3. Поле: замер, монтаж, качество (М12–М16)
- **М12.** График монтажа с загрузкой бригад и авто-подбором даты.
- **М13.** Мобильный экран замерщика/монтажника (фото, чек-лист, подпись клиента).
- **М14.** Акт выполненных работ + фотоотчёт монтажа.
- **М15.** Гарантия и рекламации: срок, история, стоимость переделки.
- **М16.** Отзыв после монтажа: авто-запрос, посадка в маркетинг.

### Фаза 4. Рост (М17–М20)
- **М17.** Автонапоминания клиенту (крон follow-up уже есть — привязать к менеджеру и стадии).
- **М18.** База клиентов и повторные продажи: кто покупал 2+ года назад, что можно допродать.

- **М20.** Клиентский кабинет B2C: статус заказа, документы, оплата, дата монтажа.

## Как выбирать очередь

1. **Сначала то, что уже написано для партнёра** (А7, А8, А6, А3) — это подключение, а не разработка.
2. **Потом швы** (А4, М1) — они дорогие, но снимают целый класс костылей.
3. **Дальше деньги** (А9–А12, М7–М9) — то, что напрямую про выручку и долги.
4. **Автоматизация в конце** — она бессмысленна, пока поток разорван.

Правило: один шаг = одна ветка = один PR, ничего не ломая в соседних контурах
(см. `docs/WORKING_RULES.md` §1 и согласование вкладок между сессиями).
