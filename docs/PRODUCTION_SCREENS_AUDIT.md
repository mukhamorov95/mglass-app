## Метод

Задание дало наполненность данными — её не повторяла. Считала другое, чего в задании не было:
**входы**. Для каждого экрана — ссылки из вкладок цеха (`ProductionTabs`), из левого меню
(`Sidebar`), из других контуров и изнутри самого цеха. Экран без данных и экран без входа —
разные диагнозы: первый не нужен, до второго не дойти.

Плюс третий срез, который решает судьбу обзорных экранов: **на какой модели прогресса стоит**.
В контуре их две — `production_tasks` (живая) и `notes.detail_stages` (переходная).

## Три находки, которых не было в задании

### 1. Результат П4 недостижим с телефона

`metrics` есть в левом меню и **отсутствует во вкладках цеха**. Левое меню — десктопное;
цех работает с телефона через `production-app.webmanifest`. То есть время этапа, ради которого
делался П4, мастер со смены не увидит. Это не «лишний экран», это отсутствующий вход.
Зеркальный случай: `activity` (#321) есть во вкладках, но нет в сайдбаре.

### 2. `guide` не просто не нужен — он вводит в заблуждение

Регламент перечисляет вкладки **«Обзор»** и **«Станции»**, убранные 14.07, и учит жать
**«Проблема»**, которой с П3 нет — вместо неё «Переделать». Рабочий, открывший регламент,
получит инструкцию к интерфейсу, которого не существует. Устаревшая инструкция хуже
отсутствующей: пустой экран человек закрывает, а этому — верит.

### 3. Три обзорных экрана вместо одного, и один из них на мёртвой модели

`board` (240 стр., «заказ × этапы»), `today` (138 стр., «пул по станциям»), `supervisor`
(443 стр., «заказы с фильтрами») — три ответа на один вопрос «что сейчас в цеху».
**`supervisor` не обращается к `production_tasks` вообще** — он целиком на `notes.detail_stages`,
то есть показывает переходную модель как единственную. Это 443 строки, которые расходятся
с остальным контуром по построению.

## Что предлагаю сделать (после «принято»)

1. **Один обзор цеха** вместо `board` + `today` + `supervisor`. За основу `board`
   (живая модель, есть внешний вход), из `today` забрать срез по станциям, из `supervisor` —
   фильтры (просрочка / проблемы / срочные) и журнал отмен. `today` оставить редиректом:
   на него ссылается дашборд CEO, ломать чужую ссылку нельзя.
2. **`orders` → режим в `my-queue`.** Оба показывают заказы с этапами, отличаются только
   охватом («мои» против «все»). При двух рабочих «мои» и «все» — почти одно и то же.
3. **Починить входы:** `metrics` во вкладки, `activity` в сайдбар.
4. **`problems` убрать из вкладок рабочего**, оставить в сайдбаре: с П3 у рабочего есть
   «Переделать», а доска андона нужна мастеру и менеджеру.
5. **Удалить `cutting`** — единственный экран во всём контуре, на который нет ни одной ссылки.
6. **`guide`** — переписать под нынешний интерфейс или удалить (вопрос 1).
7. **`earnings` и `money` — предложить вынести:** реферальные начисления и финмодель CFO
   не относятся к работе цеха и живут здесь исторически. Решение не моё — оба чужие домены.
