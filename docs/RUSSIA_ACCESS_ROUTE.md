# Маршрут: приложение работает в России при любом раскладе

Запрос владельца 29.09.2026: «нужно, чтобы на российской территории — блокировки, VPN, не VPN — работал сервис при любом раскладе. Программа нестабильно работает, это очень опасно для нас».

## Цель

Мерило готовности:
- сотрудник в России на Wi-Fi или мобильном интернете, с VPN и без, открывает приложение и работает;
- если связь рвётся, мы узнаём об этом раньше сотрудника.

Проверка — **полная загрузка** страницы (байты получены = байты ожидаемые) с российских узлов и с телефона сотрудника. Одного кода ответа мало: он приходит в первом килобайте, а обрывы случаются после (наблюдение 91).

## Как устроено сейчас (замерено 28–29.09)

```
Телефон/ПК в России ──► mglass-app.vercel.app (Vercel, зарубежные адреса)
                          ├─ страницы и API ── функции Vercel в США (iad1) ──► Supabase в Ирландии (eu-west-1)
                          └─ /supabase/*   ── перепрокси Vercel ─────────────► Supabase (Cloudflare)
Сервисы в РФ (AmoCRM, Авито, Wazzup, OnlinePBX) ──► вебхуки на mglass-app.vercel.app
```

- Масштаб: 17 учёток, за неделю активны 12, за сутки 9. База 69 МБ (196 таблиц), файлы 112 МБ (887 объектов).
- Тарифы: Vercel **Pro**, Supabase **Free**. У Free нет собственных резервных копий.
- Браузер к supabase.co напрямую не ходит: с PR #173 все его запросы идут через `/supabase/*` на домене приложения. Точка отказа для людей одна — адрес приложения.

## Этапы

### Э1. Функции рядом с базой (регион dub1) — СДЕЛАНО (PR #696, 29.09)
- **Что:** `vercel.json` → `"regions": ["dub1"]`. Функции переезжают из Вашингтона в Дублин, туда же, где Supabase (eu-west-1).
- **Даёт:** страницы с несколькими запросами к базе отвечают быстрее. Вебхук Wazzup 25–26.09 падал по 15-секундному тайм-ауту — там тоже пересечение океана.
- **Проверено:** `x-vercel-id: fra1::dub1::…`. TTFB `/login`, 12 замеров: медиана 0,33 → 0,27 с, максимум 1,04 → 0,41 с. Страницы с несколькими запросами к базе выигрывают больше: ~75 мс на каждый.
- **Риск:** низкий; откат — удалить строку.

### Э2. Российская точка входа (VPS + nginx) — НАБОР ГОТОВ, ждёт владельца: VPS и DNS
- **Что:**
  - DNS `app.mglass.pro` → российский VPS;
  - nginx с сертификатом Let's Encrypt проксирует всё на Vercel: страницы, API и `/supabase/*`.
- **Как это работает:** к российскому IP подключаются и люди без VPN, и люди с VPN. Зарубежный отрезок идёт из дата-центра, а не с домашнего или мобильного провайдера.
- **Нужно от владельца:** облачный сервер в РФ.
  - reg.ru «Облачный сервер» (аккаунт уже есть) или Selectel/Timeweb.
  - Ubuntu 24.04, 2 ГБ RAM, около 400–700 ₽/мес.
  - В панель — наш SSH-ключ (публичную часть дам).
- **Что сделать в коде:**
  - `NEXT_PUBLIC_APP_URL` → `https://app.mglass.pro`;
  - зашитые `mglass-app.vercel.app` в текстах уведомлений (Авито, OnlinePBX, ai-recommendations) — на переменную;
  - Supabase Auth: добавить адрес в разрешённые.
- **Люди:** один раз входят заново — куки привязаны к адресу. Старый адрес продолжает работать.
- **Проверка:** полная загрузка `/login` и тяжёлой страницы с российских узлов; вход и отметка этапа с телефона Никиты без VPN.
- **Риск:**
  - Vercel выпускает сертификат, когда домен смотрит не на него: challenge `/.well-known/acme-challenge/` проксируется на Vercel. Альтернатива — верификация TXT.
  - Редиректы Next.js строят адрес из Host: проксировать с `Host: app.mglass.pro`.

- **Набор:** `infra/ru-edge/` — nginx-шаблон, `setup.sh`, проба, копии, systemd-таймеры, README.
  - Конфиг проходит `nginx -t`.
  - Запасной режим (Host/SNI = mglass-app.vercel.app, без подключения домена в Vercel) проверен в контейнере на живом приложении 29.09: страницы, редиректы с переписанным адресом, `/supabase/*`, статика.

### Э2б. Браузер ни в чём не ходит на supabase.co напрямую — СДЕЛАНО, кроме второстепенного
Опись 29.09 нашла, где браузер всё ещё обращается к `*.supabase.co` мимо `/supabase/*`:
- **Подписанные ссылки на файлы:** 5 маршрутов отвечают редиректом на supabase.co. Среди них чертёж для цеха `api/b2b/drawing/[orderId]`, вложения B2B, счёт, исходник КП, вложение бухгалтерии. Ещё один отдаёт такую ссылку в JSON — `admin/glass-price-lists/[id]/file`.
- **Публичные ссылки на картинки:** сохранены в базе и выводятся в `<img>` примерно в 28 местах — материалы, КП, фото замеров, фото сдачи.
- **Второстепенное:**
  - realtime-тост в `b2b-crm/[id]`;
  - ссылка из письма сброса пароля;
  - Google Fonts на странице КП;
  - браузерный Sentry.

Лечение:
- редиректы — на тот же путь под `/supabase`;
- картинки — перехват в service worker, который регистрируется для всего приложения; отдельные страницы не правим.

### Э2в. Адрес приложения в одном месте — СДЕЛАНО (кроме Tilda и сайта зеркал)
- 7 мест зашивают `https://mglass-app.vercel.app` в тексты Telegram: Авито, OnlinePBX, ai-recommendations, `/vlad`. Перевести на `NEXT_PUBLIC_APP_URL`.
- Самовызовы сервера (`NEXT_PUBLIC_APP_URL` + `CRON_SECRET`: очередь, агенты) — на отдельную переменную с прямым адресом Vercel.
- Внешние точки на vercel.app:
  - встраивание конфигуратора на Tilda (`/embed/shower`, `docs/configurator/TILDA_EMBED.md`) — у посетителей с заблокированным vercel.app на сайте пустой конфигуратор;
  - запасной адрес заявки сайта зеркал (`sites/zerkala/lib/site.ts:115`).

Сделано 29.09:
- `lib/storageRedirect.ts` — 5 редиректов на файлы ведут на `/supabase/…` относительным адресом; JSON-ссылка прайса тоже.
- `public/sw.js` переводит запросы к хранилищу нашего проекта на `/supabase`, с сохранением заголовков (Range для видео). Хост приходит параметром `?sb=`. Регистрация — для всех вошедших (`components/StorageProxySW.tsx`), для цеха и партнёров — тем же адресом (`lib/swUrl.ts`).
- `lib/appUrl.ts`:
  - `appUrl()` — ссылки для людей, 7 зашитых мест переведены;
  - `internalAppUrl()` — самовызовы, 6 мест.

  Сегодня поведение прежнее. При переезде: `NEXT_PUBLIC_APP_URL=https://app.mglass.pro` и `INTERNAL_APP_URL=https://mglass-app.vercel.app`.

Осталось второстепенное: realtime-тост, письмо сброса пароля, Google Fonts на странице КП, браузерный Sentry. Встраивание на Tilda и адрес заявки сайта зеркал меняются вместе с Э2.

### Э3. Мониторинг из России — после Э2
- **Что:** на VPS systemd-таймер раз в минуту. Полная загрузка страницы входа и `/supabase/auth/v1/health` через оба пути (наш домен и vercel.app).
- **Сигнал:** после 3 подряд сбоев — сообщение владельцу в Telegram-бот; после восстановления — «отпустило».
- **Даёт:** «нестабильно» становится графиком — когда, сколько, на каком пути.

### Э4. Полные резервные копии в России — после Э2
- **Что:** на VPS ночью `pg_dump` всей базы (схема + данные) и выгрузка бакетов Storage. Хранить 14 дней на VPS и копию на Яндекс.Диске (папка «Бэкапы приложения»).
- **Раз в неделю:** пробное восстановление дампа в пустую базу на VPS, отчёт в Telegram «восстановлено N таблиц, M строк».
- **Нужно:** строка подключения к базе (пароль БД) — в `/root/.secrets` на VPS, в репозиторий не попадает.

### Э5. Запасной канал VPS → заграница — по сигналу Э3
- **Когда включать:** если из российского дата-центра начнут резать Vercel.
- **Что:** туннель через зарубежный VPS (AmneziaWG или VLESS+Reality), nginx переключает upstream.
- **Нужно от владельца:** зарубежный VPS, около 5 €/мес. Решение принимаем по данным мониторинга, а не заранее.

### Э6. Вебхуки на российский адрес — после Э2
- **Что:** AmoCRM, OnlinePBX, Авито, Wazzup, Telegram перенастраиваются на `app.mglass.pro`. Российские серверы → российский IP.
- **AmoCRM:** запись вебхука — это изменение настроек CRM, делает владелец или по его «да».

### Э7. Всё в России (стратегический) — решение владельца
- **Что:** приложение (`next start` в Docker) и база (Postgres или self-hosted Supabase) на российском сервере.
- **Даёт:**
  - независимость от аккаунтов Vercel и Supabase;
  - персональные данные клиентов хранятся в России. 152-ФЗ требует локализацию ПДн граждан РФ — вопрос к юристу.
- **Цена:** недели работы; эксплуатация (обновления, копии, дежурство) на нас. ИИ-функции всё равно выходят за рубеж через узел Э5: Anthropic и OpenAI Россию не обслуживают.

## Найдено попутно (вне маршрута)

- **Запись в AmoCRM вопреки правилу «только чтение».** POST заметок в `cron/process-queue` (ежедневно), `amo/calls/analyze`, `admin/integrations/backfill`; POST задач в `amo/calls/analyze`. Похоже на сознательную синхронизацию сообщений в CRM (PR #193 её чинил). Решение за владельцем.
- **Вход владельца.** Коды 2FA идут через Telegram (`OWNER_2FA_ENABLED`). Если Telegram заблокируют, при включённой 2FA владелец не войдёт; нужен запасной путь.
- **Ошибка:** `app/api/auth/setup-org/route.ts:72` обращается к `${SUPABASE_URL}/api/auth/setup-org` — такого адреса у Supabase нет.

## Грабли

- `vercel logs --json` (CLI 52.2.1) повторяет строки: 5000 строк = 77 уникальных `id`. Дедуплицировать по `id` (наблюдение 121).
- Страна в логах Supabase — это узел Vercel, который проксирует `/supabase/*`, а не человек (наблюдение 123).
- `auth.users.last_sign_in_at` — последний ввод пароля. Последний заход — `auth.sessions.updated_at` (наблюдение 122).
- check-host видит только начало ответа. «200» не значит «страница загрузилась» (наблюдение 91).
- С Mac владельца проверять доступность из России нельзя: Happ ведёт `.ru` напрямую, а зарубежное — через туннель.

## Потолок

- **«Белые списки» мобильного интернета** (отключения, когда открываются только разрешённые сервисы). Наш сервер в них не входит. Спасает только Wi-Fi на проводном интернете; в цеху и офисе он должен быть.
- **Полное отключение зарубежного интернета** («суверенный режим»). Э2–Э5 не помогут, поможет только Э7. ИИ-функции при этом не работают в любом случае.
- **Блокировка аккаунтов Vercel или Supabase** (санкции, оплата). Э4 даёт данные, Э7 — место, где их поднять.
