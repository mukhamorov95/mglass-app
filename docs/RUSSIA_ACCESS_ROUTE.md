# Маршрут: приложение работает в России при любом раскладе

Запрос владельца 29.09.2026: «нужно, чтобы на российской территории — блокировки, VPN, не VPN — работал сервис при любом раскладе. Программа нестабильно работает, это очень опасно для нас».

## Цель

Мерило готовности:
- сотрудник в России на Wi-Fi или мобильном интернете, с VPN и без, открывает приложение и работает;
- если связь рвётся, мы узнаём об этом раньше сотрудника.

Проверка — **полная загрузка** страницы (байты получены = байты ожидаемые) с российских узлов и с телефона сотрудника. Одного кода ответа мало: он приходит в первом килобайте, а обрывы случаются после (наблюдение 91).

## Как устроено сейчас (замерено 28–29.09)

```
Телефон/ПК в России ──► mglass-app.vercel.app (Vercel, зарубежные адреса)
                          ├─ страницы и API ── функции Vercel в США (iad1) ──► Supabase в Ирландии (eu-west-1)
                          └─ /supabase/*   ── перепрокси Vercel ─────────────► Supabase (Cloudflare)
Сервисы в РФ (AmoCRM, Авито, Wazzup, OnlinePBX) ──► вебхуки на mglass-app.vercel.app
```

- Масштаб: 17 учёток, за неделю активны 12, за сутки 9. База 69 МБ (196 таблиц), файлы 112 МБ (887 объектов).
- Тарифы: Vercel **Pro**, Supabase **Free**. У Free нет собственных резервных копий.
- Браузер к supabase.co напрямую не ходит: с PR #173 все его запросы идут через `/supabase/*` на домене приложения. Точка отказа для людей одна — адрес приложения.

**Закон (сырой текст КонсультантПлюс, 13.10):** 152-ФЗ ст. 18 ч. 5 в редакции от 28.02.2025 — хранение и обработка персданных граждан РФ «с использованием баз данных, находящихся за пределами территории Российской Федерации, не допускаются»; исключения п. 2, 3, 4, 8 ч. 1 ст. 6, исполнения договора среди них нет. Значит, копия клиентской базы в Ирландии — тоже нарушение (прочтение, подтвердить у юриста). Передача за рубеж (ст. 12) — отдельно, с уведомлением РКН. Штраф КоАП 13.11 ч. 8 — юрлицу 1–6 млн ₽, повтор (ч. 9) — 6–18 млн ₽. В Supabase уже 26 таблиц / 51 колонка с данными клиентов.

**Вариант «разделить» (персданные в РФ, остальное как было) — разобран 13.10 по вопросу владельца:** законен, но дороже полного переезда: две системы вместо одной, правка 26 таблиц и экранов, где показаны имя и телефон, вебхуки с перепиской должны писать сразу в РФ, изоляция менеджера — в двух местах, Vercel Pro (≈1 680 ₽) остаётся вместе с российским сервером. Сервер на производстве годится для копий (NAS), не для живой базы: свет и интернет офиса — потерянные заявки из вебхуков.

**Три вещи до решения:**
1. **Selectel о VDS дословно: «Соответствует ли VDS 152-ФЗ? Нет, не соответствует».** Хранение в РФ это не отменяет; нужен ли провайдер с аттестацией — вопрос юристу. Если нужен — облачный сервер Selectel «152-ФЗ до УЗ-1», дороже (от 948,50 ₽ за самую малую конфигурацию, цену 8 ГБ страница не отдаёт).
2. **ИИ-функции.** России нет в списках поддерживаемых стран Anthropic, OpenAI и Gemini (сырой HTML; у Anthropic: «Any country or region not listed is unsupported… Use by entities incorporated or headquartered in an unsupported region»). Это относится и к нынешней схеме через Vercel; переезд сервера статус не меняет. Варианты: оставить как есть на свой риск, перейти на провайдера, официально работающего в РФ, выключить. Решение — владелец и юрист; узел-обход в план не входит.
3. **Неоплата = удаление.** Selectel: при нехватке баланса «VDS сервер автоматически заблокируется», через 14 дней «VDS сервер удалится. Данные с локального диска тоже удалятся». Автоплатёж и уведомления о балансе — обязательны.

**Требования (проверено по коду и базе 13.10):** Supabase self-hosting — минимум 2/4/40, рекомендовано 4/8/80; Edge Functions, imgproxy и Realtime не нужны (Realtime-публикация пуста). `next start` покрывает `after()`, middleware и edge-маршрут `cron/ping`; 12 маршрутов до 300 с → nginx `proxy_read_timeout` ≥ 310 с. Сборка — в GitHub Actions (typecheck ест ~8 ГБ). Кроны `vercel.json` — в UTC, на сервере cron с `CRON_TZ=UTC` и `flock`. База: Postgres 17.6, 212 таблиц, 321 политика, 52 функции, 8 бакетов / 1 030 объектов, 18 пользователей. Триггер `on_auth_user_created` и 7 политик storage обычная выгрузка не переносит — отдельный diff схем `auth,storage`. Пароли сотрудников сохраняются (официальный гайд «Restore a Platform Project to Self-Hosted»), но ключи токенов новые — каждый один раз войдёт заново.

## Грабли

- `vercel logs --json` (CLI 52.2.1) повторяет строки: 5000 строк = 77 уникальных `id`. Дедуплицировать по `id` (наблюдение 121).
- Страна в логах Supabase — это узел Vercel, который проксирует `/supabase/*`, а не человек (наблюдение 123).
- `auth.users.last_sign_in_at` — последний ввод пароля. Последний заход — `auth.sessions.updated_at` (наблюдение 122).
- check-host видит только начало ответа. «200» не значит «страница загрузилась» (наблюдение 91).
- С Mac владельца проверять доступность из России нельзя: Happ ведёт `.ru` напрямую, а зарубежное — через туннель.
- SSH с Mac владельца на сервер через Happ временами висит на обмене баннерами, по 6 попыток подряд. Нужны повторы с ограничением по времени (`perl -e 'alarm N; exec @ARGV' ssh …`). Файлы передавать одной командой (`base64` в аргументе или `tar | ssh`), а не через scp. Долгие команды запускать на сервере через `nohup` с журналом: оборванная сессия не должна запускать их повторно.
- При тайм-ауте `curl -w` сам печатает `000 0 25.0` и выходит с ошибкой; `|| echo` поверх этого склеивал две строки в журнале пробы.

## Потолок

- **«Белые списки» мобильного интернета** (отключения, когда открываются только разрешённые сервисы). Наш сервер в них не входит. Спасает только Wi-Fi на проводном интернете; в цеху и офисе он должен быть.
- **Полное отключение зарубежного интернета** («суверенный режим»). Э2–Э5 не помогут, поможет только Э7. ИИ-функции при этом не работают в любом случае.
- **Блокировка аккаунтов Vercel или Supabase** (санкции, оплата). Э4 даёт данные, Э7 — место, где их поднять.
