# Стандартная линейка душевых и партнёры-рекомендатели — маршрут

Задача владельца 17.09.2026: стандартные позиции на склад (заготовки) → понятная
юнит-экономика каждой позиции → цена на сайте, с которой мы и конкурентны, и
зарабатываем → партнёрский бонус для дизайнеров и прорабов → кабинет партнёра
(сколько заказов от него, на какую сумму, какой бонус заработал).

Разбор рынка: отчёт «Рынок готовых душевых» (claude.ai/artifact/YLbUZXcp9DZisKQevv72mJ),
второй мозг `01-БИЗНЕС/ОБЩЕЕ/рынок/готовые-душевые-ограждения.md`.

## Цель

1. По каждой позиции видно: себестоимость до клиента построчно (итог раскрывается в
   строки, строки сходятся с итогом), цена по формуле компании, цена безубыточности,
   сколько остаётся при выбранной цене на сайте, какой бонус партнёру выдерживает цена.
2. Цены конкурентов рядом с нашей — ориентир для цены на сайте.
3. Дизайнер или прораб по своей ссылке видит: число заказов от него, их сумму,
   начисленный и выплаченный бонус. Больше ничего о компании.

### Э1. Формула юнит-экономики и стартовый набор позиций — СДЕЛАНО 17.09

- `lib/standardLine/economics.ts` — формула, тесты `__tests__/standardLine/economics.test.ts`.
- `lib/standardLine/catalog.ts` — 10 позиций: walk-in 900/1000/1200 и дверь в нишу
  1000/1200, стекло 8 мм прозрачное, чёрный и хром; цены конкурентов на 16.09.
- `lib/calc/buildPrice.ts` — расчёт «Расчёта» вынесен из `/api/calc/build`, маршрут
  зовёт его же (поведение не менялось).

**Формула.**

```
Себестоимость до клиента = Стекло + Фурнитура и профиль + Упаковка + Сборка + Доставка   (₽)
Доли от цены            = Налог и расходы + Бонус партнёру + Эквайринг + Резерв          (%)

Цена по формуле компании = Себестоимость / (1 − маржа − налог) / (1 − бонус − эквайринг − резерв)
Цена безубыточности      = Себестоимость / (1 − налог − бонус − эквайринг − резерв)
Остаётся при цене Ц      = Ц − Себестоимость − Ц × (налог + бонус + эквайринг + резерв)
Макс. бонус при цене Ц   = 100 − Себестоимость/Ц × 100 − налог − эквайринг − резерв − целевая маржа
```

Первая строка — `calcFinancialModel` с `partnerPercent = бонус + эквайринг + резерв`
(решение CFO: доля партнёра — gross-up). При этой цене остаётся не ровно маржа, а
`маржа × (1 − доли) − налог × доли` — так и показывать, не прятать.

**Проверка:** тесты (8) + прогон 10 позиций через живые справочники.

## Решения по умолчанию (владелец может поменять)

| Параметр | По умолчанию | Почему |
|---|---|---|
| Бонус партнёру | 10% от оплаченной суммы | Рынок 7–10% в среднем сегменте (Флатика, обновл. 02.07.2026); в базе уже «Дизайнер 10%» |
| Когда начисляется | После полной оплаты сделки | Не платить бонус за неоплаченное |
| Налог и расходы | 12% из `financial_settings` (shower_budget) | Канон; реальный режим налогов — этап Ф4 финмодели |
| Целевая маржа | 40%, минимум 25% из `financial_settings` | Канон |
| Доставка в изделии | 0 при самовывозе / отдельной строкой | 4 000 ₽ на изделие — до трети себестоимости walk-in |
| Эквайринг, резерв | не заполнены | Нет ставки банка и данных о бое |

## Грабли

- **Стекло для M-Glass — не себестоимость компании.** `buildPrice` берёт стекло по B2B-цене
  со скидкой M GLASS 20% (walk-in 1200: 5 952 ₽), переменные затраты цеха на ту же
  панель — 4 002 ₽ (кромка — оклад, не входит). Для решения «выгодна ли позиция
  компании» смотреть обе цифры.
- **Ширина у М1.** По умолчанию введённая ширина — проём, стекло 62% от неё. Для
  стандартной позиции нужен `glassSpan: 'panel'`, иначе walk-in «1200» считается как 744.
- **Безубыточность — сумма долей, а не произведение.** Налог и бонус берутся с одной
  конечной цены. Первый вариант формулы перемножал доли; тест поймал 224 ₽ «остатка»
  там, где должен быть ноль.
- **Зачистка RLS разовая.** 20260814 закрыла всё на свой день; новые таблицы снова
  пришли с `using (true)`. Каждая новая таблица — сразу с `not is_partner()`.
- **Новая роль для партнёра-рекомендателя открыла бы всё.** 121 политика отсекает только
  `role = 'partner'`, а API пропускают любого вошедшего. Поэтому кабинет по ссылке, без логина.

## Потолок

- Упаковка, эквайринг и бой не посчитаются, пока нет цифр — страница покажет их пустыми.
- Сайт не продаёт и не принимает оплату: платёжные адаптеры — заглушки, заявки виджета
  не сохраняются. Цена «на сайте» здесь — расчётная, не опубликованная.
- Выплата бонуса — отметка владельца, без банковской интеграции и без договора
  с партнёром (договор и НДФЛ/самозанятость — вопрос бухгалтерии).
- 12% — «налог и расходы» одной цифрой, не реальный режим налогообложения.
