# Telegram-бот M-Glass — аудит навигации и ТЗ на переработку (2026-07-07)

Задача владельца #1 из owner_tasks: «при каждом заходе — главное меню, не застревать в подменю; аудит структуры меню; ТЗ на переработку навигации».

## Текущая структура (по коду app/api/telegram/webhook/route.ts)

**Главное меню (MAIN_MENU):**
📊 Дашборд · 🤖 Агенты · 🧮 Расчёт цены · 📋 Лиды · 💬 Написать клиенту · 📝 Задача в систему

**Команды:** /start /menu /d /dashboard /agents /calc /task /health

**Режимы (state в telegram_sessions):**
| Режим | Вход | Выход |
|---|---|---|
| calc_input → calc_confirm | /calc, menu:calc | Меню / после расчёта |
| task_input | /task, menu:task | Меню (остаётся для диктовки подряд) |
| train_input | menu:train | после сохранения |
| lead_send_msg | lead:msg:* | после отправки |
| leads_list / main_menu | навигация | — |

## Проблемы (аудит)

1. **[ИСПРАВЛЕНО `c8299cd`+текущий коммит] Застревание в режиме.** Сессия жила вечно: зашёл в /calc неделю назад — сегодня любой текст трактуется как размеры изделия. Голос ВСЕГДА уходил в калькулятор, даже в других режимах.
   → Фиксы: TTL режима 30 минут (getSession: старый state → main_menu); голос уважает активный режим; /start и «🏠 Меню» сбрасывают явно.
2. **Нет реплай-клавиатуры (постоянной).** Всё на inline-кнопках под сообщениями: когда сообщение уезжает вверх, «дверей» не видно. Пользователь пишет текст в никуда → фолбэк кидает в меню, но выглядит как «бот не понял».
3. **Ассиметрия команд и кнопок.** /health есть командой, но нет в меню; «Обучение AI» (train) есть callback'ом menu:train, но не видно точки входа в MAIN_MENU.
4. **Нет подтверждения контекста.** В режиме (например «Задача») длинное сообщение-приглашение уезжает; нет постоянного маркера «ты в режиме X, выход — /menu».
5. **Callbacks без владельца-ролей.** Меню одно для всех авторизованных: рабочему цеха не нужны «Агенты» и «Лиды». (Сейчас в боте фактически один пользователь-владелец — не критично, но заложить.)

## ТЗ на переработку навигации

### Этап 1 (сделано в этом коммите)
- [x] TTL режимов 30 минут → автовозврат в главное меню.
- [x] Голос маршрутизируется по активному режиму.
- [x] Кнопка «🏠 Меню» во всех приглашениях режимов (task добавлена; calc/lead уже были).

### Этап 2 (рекомендуется)
1. **Постоянная reply-клавиатура** (Telegram reply keyboard, не inline): `[📊 Дашборд] [🧮 Расчёт] / [📝 Задача] [📋 Лиды] / [🏠 Меню]` — всегда под полем ввода, не уезжает с историей. Inline-кнопки остаются для действий над конкретным сообщением (подтвердить расчёт, оплатить, открыть лид).
2. **Маркер режима**: при входе в режим отправлять короткий пин-стиль заголовок «🧮 РЕЖИМ РАСЧЁТА (выход: /menu)»; при TTL-сбросе — «⏳ Режим закрыт по неактивности, вот меню».
3. **Единый /menu хэндлер** для текстов «меню», «выход», «отмена», «stop» в любом режиме.
4. **Разделы меню по ролям** (когда появятся другие пользователи): владелец — всё; production — только Дашборд цеха + Задача; manager — Расчёт + Лиды.
5. **/help** — карта команд одной страницей.
6. Убрать мёртвые пункты: «Обучение AI» вывести в меню владельца или удалить callback.
