Что относится именно к этому файлу и в `CLAUDE.md` не дублируется:

- при задаче по конкретной теме — соответствующий раздел `docs/AUDIT_2026-06-30.md`.

## 1. Инварианты (нарушать нельзя)
1. **AmoCRM — только чтение.** Никаких POST/PATCH/DELETE к CRM. ⚠️ Известно нарушение (`cron/process-queue`, `amo/calls/analyze`) — статус решается владельцем, см. AUDIT → «Открытые решения». Новых записей не добавлять.
2. **Деньги — детерминированный TypeScript.** LLM никогда не вычисляет цену. Формула: `Цена = Себестоимость / (1 − маржа% − налог%)`, налог 12% (B2C), маржа из `financial_settings`. Накладные уже в марже.
3. **CFO (`/cfo/`) — единственный источник финансовой детали.** Маржа/себестоимость/P&L не добавляются в `/admin`, `/ceo`, `/commercial` без согласия владельца.
4. **Один раздел = одно дерево маршрутов.** Доступ проверяется в `layout.tsx` раздела через `getRole()` + `canAccessRoute()`.
5. **Изоляция данных менеджера** по умолчанию; расширение — только через флаг (`can_view_all_deals` и т.п.).
6. **Service-role клиент (`createServiceClient`) — только на сервере и только после собственной проверки прав.** Он обходит RLS.
7. **Воронка/зоны** — строго по таблице в `SYSTEM.md`/`PROJECT_RULES.md`; менять зоны = менять и `salesMonitor.ts`.

## 2. Протокол изменения (каждая правка)
0. **Старое — под сомнением** (правило владельца, 04.09.2026). Если правка обращается к экрану/коду/таблице, сделанным 2–4 месяца назад, — сначала короткий разбор этого старого и вывод владельцу, ДО того как строить поверх. Четыре оси: **финансы** (цена сходится со справочником, нет молчаливых фолбэков и ручных таблиц), **визуал** (видно, из чего сложилась цифра), **логика** (семантика полей = то, что человек реально вводит), **безопасность** (RLS, проверка доступа, service-role только на сервере). Ломать сразу нельзя, наследовать молча — тоже. Цена вопроса известна: фурнитура душевой занижала на 20–99%, walk-in считал стекло за 62% заказанного — оба экрана выглядели рабочими.
1. **Анализ** — прочитать затрагиваемый код и его читателей/писателей; не править вслепую.
2. **План** — минимальное изменение, которое решает задачу и ничего не ломает. При выборе подхода — выбрать архитектурно лучший и кратко объяснить.
3. **Правка** — точечно. Не удалять и не переписывать рабочее без явного согласия (см. §3).
4. **Проверка** (обязательно перед «готово»):
   ```bash
   cd mglass-app
   npx tsc --noEmit      # типы
   npx eslint .          # линт (не вводить новых ошибок)
   npx vitest run        # тесты
   npm run build         # при правках routing/RSC/middleware
   ```
5. **Обновить `SESSION.md`** (текущая задача / что сделано / следующий шаг / контекст / открытые вопросы).

## 3. Спрашивать ДО действия (не делать автономно)
- Удаление данных, таблиц, файлов; «зачистка» того, что выглядит мусором, но не нами создано.
- Любая запись в AmoCRM.
- Включение RLS на таблице, которую читают анон/клиентские калькуляторы (риск сломать чтение).
- Смена ENV-секретов; перевод cron/webhook-проверок в fail-closed без подтверждения, что секрет задан в проде.
- Необратимые/деструктивные действия, force-push в основную ветку.
> Если найденное противоречит тому, как это описано (рабочий код против правила) — **вынести владельцу**, а не «исправлять» молча.

## 5. Автоматизация (чтобы не жечь токены на повторную ловлю проблем)
- Перед коммитом — прогон §2.4 (планируется pre-commit/CI hook: typecheck+lint+test).
- Планируется **тест-страж**: падает, если мутационный роут в `api/admin`,`api/cfo`,`api/commercial`,`api/orders` не вызывает guard (`requireOwner`/`requireAdmin`/проверку владельца) — чтобы дыры доступа не возвращались.
- Планируется **тест целостности цен**: одна и та же конфигурация изделия даёт одинаковую цену в web-калькуляторе и в quickCalc/AI.

## 6. Технологический контекст
- **Next.js 16 + React 19** — отличается от training data. Перед routing/RSC/middleware читать `node_modules/next/dist/docs/`. `cookies()`/`headers()` — `await`.
- Supabase-клиенты: `supabase-server` (анон+cookies, RLS), `supabase-service` (service-role, обход RLS, только сервер), `supabase-browser` (`createClient`/`createScopedClient`).
- Стиль: комментарии только если WHY неочевиден; Tailwind инлайн; UI/копи/комментарии — по-русски. Палитра: text `#111110`, bg `#f5f5f3`, border `#e4e4e0`, muted `#9a9a95`.
