## 5. Архитектура — один поток

`BuildRequest` (модель, габариты, цвет, стекло, choice/qtyChoice, вариант, `panels?`, `drawn?`) — одна спецификация для виджета, «Расчёта» и чертежа; ИИ (Ч2) только заполняет её поля
→ геометрия → `computeKitQuantities` (роли, количества, куски)
→ комплект: слот роли → позиция библиотеки = одна физическая деталь. Цвет — ось цен по суффиксу. Каждая длина хлыста — `stocks[]` со своим `CatalogRef` (`pricing.ts:71`). ★ — умолчание, ходовые — ★ владельца в справочнике
→ раскрой `planBars` / `planOrderCutting`: пул по `itemId + finishId`, min(общий, поштучный), экономия строкой заказа
→ себестоимость по фондам (`lib/pricing/orderFunds.ts`): материалы, сдельная, налог, продажи → «Остаётся с заказа»
→ цена: сейчас /(1 − 40% − 12%), после Ш1 — `priceForTarget`
→ менеджер видит строки с артикулом, хлыстом, остатком, датой цены и метками; /cfo — фонды; клиент — итог, `complete`, состав названиями, «действительна до».

**Споры, решённые здесь:**
- Эталон — одна фикстура на 2200 по ценам листа 01.10: там любое правило даёт 2 петли. На 2310 проверяем только выбор хлыстов до решения 2.
- Ключ пула — `itemId + finish` после чистки. В `base` зашита длина (FDPA-55.22 / 55.3), а `itemId` без цвета мешает отделки в одном хлысте (наблюдение 193).
- Хром — сначала метка, `complete` не трогаем: экран обнуляет цену при неполном расчёте (`page.tsx:283, 298`).
- `SPLICEABLE` (`kit.ts:312`) не трогаем: с хлыстом 2,5 м стыковка нужна только кускам длиннее 2,5 м.
- Низ профиля — флаг варианта с прежним умолчанием, иначе меняются 3D и сайт у всех моделей.
- Quote переходит на общий движок только с версией, где есть цены стекла: в `PriceSnapshot` их нет (`priceVersion.ts:13-17`).
- Сайт ≤2200 (`arrangement.ts:32`); «Расчёт» считает 2310 с пометкой «нестандарт».

## 8. Грабли

- Аналог у другого поставщика меняет отверстия в стекле: межось 210 → 200, Ø12 под торец штанги. Чертёж правится до закалки (наблюдение 172).
- Снимок цен — не главная ошибка: на 0245 дрейф 57 ₽ против ~7 000 ₽ на душевую от выбора основного артикула (наблюдение 188).
- Петли — по весу двери и паспорту, не по привычке. Магнитные уплотнители 90° и 180° — разные артикулы.
- Коды цветов уплотнителей — своя ось: CL — прозрачный, GG — серый, не оружейная сталь (наблюдение 195).
- Копии позиций гасят общий раскрой, а `Math.max` прятал, что FFD хуже поштучного (наблюдения 189, 193).
- Хромовый фолбэк убирать через перепись: 27 из 29 дыр закрывает маппер (наблюдение 192).
- Тест эталона утверждает цель, а не алгебру формулы (наблюдение 186).
- Читатель, теряющий поля, перед писателем целого объекта — это удаление (наблюдение 196, закрыто #781). Та же ловушка у `cfo_settings` и у чистки при открытой админке.
- КП уходило клиенту с шаблонной комплектацией: «белая фурнитура» при чёрной на чертеже.
- Экран обнуляет цену при неполном расчёте — новая причина missing без метки отправит менеджера в «Быстрый».
- Никто не проверил, почему менеджеры не пользуются «Расчётом».
- Звезда сдвигает `updated_at`. Импорт с заменой (по умолчанию, `SupplierImport.tsx:52`) удаляет строки вместе со звёздами владельца.
- Пикер плодит копии: чистка без починки писателя вернёт дубли.
- В фикстуру — только артикулы и размеры, без адреса и имени клиента (наблюдение 181).
- Панель планировала уже влитые #780/#781 по сдвинутым строкам. Перед этапом — `git log origin/main` по затронутым файлам (наблюдение 197).

## 9. Потолок

- Точность ограничена датой импорта прайса; наличие у поставщика не видно.
- Эталон один (распашные М4/М7). Раздвижные М8–М12, М11 и premium без своих заказов не доказаны — нужны 2–3 реальных.
- Нестандартную топологию алгоритм останавливает, но не считает.
- ИИ-разбор не даёт «без сбоев» сам: гарантию дают остановки и подтверждение менеджера. Автоправки чертежа стекла нет.
- Обрезки без журнала не зачесть: склад пуст.
- Фонды — план; факт выплат сверяется по ДДС.
- Точная цена на сайте — только на сетке ≤2200.
