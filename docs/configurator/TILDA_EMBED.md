# Виджет 3D на mglass.pro (Tilda)

Виджет живёт по адресу `https://mglass-app.vercel.app/embed/shower` и открыт без
авторизации — маршрут `/embed/` пропущен в `middleware.ts`. Заголовков, запрещающих
показ в рамке, нет, поэтому Tilda его покажет.

## Что вставлять

Tilda → страница → **Другое → T123 «HTML-код»**. Внутрь целиком:

```html
<div style="max-width:1240px;margin:0 auto;">
  <iframe id="mglass-3d"
    src="https://mglass-app.vercel.app/embed/shower"
    title="Конструктор душевой перегородки M-Glass"
    style="width:100%;height:1800px;border:0;display:block;"
    loading="lazy"></iframe>
</div>
<script>
(function () {
  var frame = document.getElementById('mglass-3d');
  var ORIGIN = 'https://mglass-app.vercel.app';
  window.addEventListener('message', function (e) {
    if (e.origin !== ORIGIN) return;              // чужие сообщения не слушаем
    var d = e.data || {};
    if (d.type === 'mglass-embed-height' && d.height) {
      frame.style.height = Math.max(600, d.height) + 'px';
    }
    if (d.type === 'mglass-shower-config') {
      // Клиент отправил заявку. d.config — модель, габариты, стекло, цвет, цена «от».
      // Сюда же можно повесить цель Яндекс.Метрики, когда понадобится.
    }
  });
})();
</script>
```

Высота задана 1800 px только на первые доли секунды: виджет сам сообщает свою
высоту наружу (`mglass-embed-height`), и рамка подстраивается. Без этого на
телефоне внутри рамки появляется вторая полоса прокрутки, и человек в ней теряется.

## Вход сразу на нужную модель

Карточка вида перегородки на сайте ведёт не на общий экран выбора, а прямо в сборку:

```
https://mglass-app.vercel.app/embed/shower?model=М7
```

Коды: М1 стационарная, М2 прямая распашная, М4 стекло-дверь-стекло,
М7 угловая распашная, М8, М9, М10, М11 пятигранник, М12.
Неизвестный код просто откроет экран выбора — сломать нельзя.

## Заявки приходят и без Tilda

**До 02.10.2026 это было неправдой.** Кнопка «Оставить заявку» только отправляла
сообщение в родительское окно и писала «Заявка отправлена». Телефона она не
спрашивала, в базу и Telegram ничего не уходило: в `site_leads` за всё время не
было ни одной строки. Встраивать виджет до Ш3 было нельзя.

С Ш3 (маршрут `SHOWROOM_COST_ROUTE.md`, решение 11 от 02.10) заявка уходит на сервер:

- кнопка открывает форму из имени и телефона, телефон обязателен; есть скрытое поле
  от ботов;
- форма шлёт `/api/configurator/lead` вместе с составом: модель, размеры, стекло,
  цвет, выбор фурнитуры, цена «от». Состав ложится в `site_leads.config`;
- в приложении заводится сделка с источником «Заявка с сайта». Если телефон уже
  есть в живой сделке, вторая не заводится, заявка ложится в неё;
- владельцу в Telegram приходит состав и две кнопки: «Открыть расчёт»
  (`/calculator/build?lead=N`, тот же состав в «Расчёте») и «Сделка №N»;
- AmoCRM не трогается.

Сообщение `mglass-shower-config` в родительское окно по-прежнему уходит — после
успешной отправки и только для аналитики Tilda.

**Перед встраиванием на публичный сайт:** цена «от N ₽» в виджете пока считается
не так, как в «Расчёте» менеджера. Одна цена — этап Ш2, он ждёт решения 10. Клиент
запомнит число с сайта, а менеджер назовёт другое.

## Проверено 04.09.2026

Анонимный заход на прод: страница отдаёт 200, без `X-Frame-Options` и CSP.
Экран выбора рисуется с фотографиями моделей, `?model=М7` открывает сборку сразу.
Телефон 375 px: две колонки карточек, горизонтальной прокрутки нет, сцена
получает канвас 317×420 при плотности 2. Ошибок в консоли нет.
