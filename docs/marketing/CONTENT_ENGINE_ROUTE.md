# Контент-машина M-Glass — маршрут (19.11.2026)

Задача владельца (18–19.11): ИИ-агент отвечает за маркетинг. Фото из группы «Монтажи» → карточка объекта
с размерами, ценой и чертежами → статья на сайте → пересказы на площадках → статистика по каждой
публикации и по каждому источнику: сколько перешли на сайт и сколько оставили заявок. Всё видно на
одном экране, человек только утверждает. Ничего не нарушаем: ни законы, ни правила площадок.

Образец результата — первая страница объекта (#1082):
https://www.mglass-zerkala.ru/raboty/zerkala-ot-pola-do-potolka-zhk-sobytie

## Цель и мерило

| Что меряем | Где берём |
|---|---|
| Объектов опубликовано в неделю | реестр публикаций (Э1) |
| Переходы на сайт по каждой площадке и посту | UTM-метки + Метрика |
| Заявки по каждой площадке | заявки сайта с UTM + тег в AmoCRM |
| Индекс страниц объектов | Вебмастер, Search Console |
| Просмотры и реакции | статистика площадок (где есть API) |

Готово, когда на одном экране видно: «пост VK от 25.11 — 340 просмотров, 12 переходов, 1 заявка».

## Команда агентов

Один главный и семь исполнителей. Главный не пишет тексты — решает, что делать на неделе, и сводит отчёт.

| Агент | Делает | Вход → выход |
|---|---|---|
| **Маркетинг-директор** (главный) | план недели: какие объекты, какие площадки; разбор статистики; что усилить, что бросить | статистика → план и задачи остальным |
| **Сборщик объекта** | по сообщению в «Монтажах» находит номер заказа → папку на Диске → чертежи и КП; заполняет карточку по `docs/sites/OBJECT_CARD.md`; адрес → ЖК, застройщик | фото + номер → черновик карточки |
| **Фоторедактор** | отбор кадров, обрезка, свет, удаление мусора с пола; изделие не меняет | сырые кадры → 5–8 кадров для сайта |
| **Автор** | статья объекта для сайта (как #1082), пересказы для площадок — каждый своими словами | карточка → тексты |
| **Юрист-модератор** | проверка каждого текста и фото: закон о рекламе, персональные данные, правила площадки, правдивость | текст → «можно / нельзя и почему» |
| **Публикатор** | публикует утверждённое там, где есть API; где нет — готовит пакет «скопировать и вставить» | утверждённый пакет → ссылка на пост |
| **Аналитик** | раз в сутки собирает просмотры, переходы, заявки по каждой публикации | API площадок, Метрика, AmoCRM → дашборд |
| **SEO-аналитик** | индекс страниц объектов, позиции, переобход | Вебмастер, GSC → дашборд |

Человек в цепочке — владелец (или офис-менеджер по его поручению): **утверждает каждую публикацию одной
кнопкой** в дашборде или в Telegram-боте. Правило проекта: наружу от имени компании ничего не уходит без
«да» человека. Автопубликация без утверждения — только по отдельному решению владельца и только для
площадок, где за месяц не было ни одной правки.

## Этапы

**Э0. Правила площадок и закон — СДЕЛАНО 19.11 → `docs/marketing/RULES.md`.** Открытое — там же, §7. Документ `docs/marketing/RULES.md`: по каждой площадке —
что можно публиковать, нужна ли маркировка рекламы (ERID), есть ли API публикации и статистики, лимиты,
за что банят. Проверка по первичным источникам (скилл `fact-check`), с датой.
Уже известно и требует проверки в Э0:
- Instagram: Meta признана в РФ экстремистской; реклама на её ресурсах запрещена — вести трафик из
  Instagram **высокий риск**, не начинаем без проверки Э0;
- реклама в Telegram и YouTube — по тексту ч. 10.7 норма в силе с 01.09.2025 (дата 2027 из базы 05.10 —
  пересказ «послабления», первоисточника нет; RULES.md §2.2);
- маркировка: нужна ли для постов о своих работах в своих сообществах;
- фото квартир клиентов: без адреса и людей; ретушь не меняет изделие (недостоверная реклама);
- API: VK и Telegram-бот — есть; Дзен, VC.ru, Яндекс Бизнес, 2ГИС — проверить; Авито — API платного тарифа.
Риск: низкий. Точка остановки: документ сам по себе страхует от бана.

**Э1а. Раздел «Маркетинг» — СДЕЛАНО 19.11.** Владелец: «только то, что используем; первым — статистика».
`/marketing` = Статистика (заявки amo по каналам и сайтам, `lib/marketing/channels.ts`), Агенты (реестр
`lib/marketing/agents.ts` + порядок работы `.claude/agents/marketing-*.md`), Сайты (`lib/marketing/sites.ts`,
чек-лист нового сайта). Удалены пустые экраны: контент-план, дневной план, партнёры, акции, задачи,
AI-маркетолог, видео, SEO-заявки (читал `crm_leads source=site` — 0 строк, сайты пишут в amo).
Video Factory и медиатека — инструменты «Продвижения», переехали туда в меню. Отзывы — данные целы, в меню нет.
Не подключено: визиты Метрики (нужен OAuth-токен владельца), Вебмастер/GSC API.

**Э1. Реестр публикаций и дашборд.** `/marketing/publications`: объект → публикации (площадка, ссылка,
дата, статус «черновик / на утверждении / опубликовано»), у каждой своя UTM-ссылка на сайт.
Публикуем пока руками, но всё уже учитывается. Таблицы `content_objects`, `content_publications`,
`content_metrics`. Старые пустые экраны `/marketing` — пересмотреть, лишнее убрать (с вашего «да»).
Риск: низкий. Проверка: пост VK с UTM → визит в Метрике с этой меткой.

**Э2. Сборщик объекта.** Сообщение в «Монтажах» с номером заказа → карточка-черновик: фото, номер,
папка Диска, чертежи (лист без штампа, как в #1082), КП → цены по позициям, адрес → ЖК (адрес в базе не
хранится). Владелец видит черновик и дополняет.
Риск: средний — подписи в группе неоднородные, номер заказа есть не всегда; доступ к Диску по API —
проверить (с Mac владельца Диск не синхронизировался из-за VPN).

**Э3. Тексты и фото.** Автор и Фоторедактор готовят статью и пересказы под каждую площадку; Юрист
проверяет; владелец утверждает в Telegram одной кнопкой.
Риск: средний — правдивость фото после обработки; цена в тексте только из КП.

**Э4. Публикация.** Сайт зеркал — сборка и выкладка (сейчас вручную через панель reg.ru — для
автоматики нужен доступ по FTP/SSH); Telegram-канал и VK — по API; остальные — пакет для ручной вставки.
Риск: средний — выкладка сайта сейчас ручная.

**Э5. Статистика.** Ежедневный сбор: Метрика (визиты и цели по UTM), VK (охват, клики), Telegram
(просмотры), заявки сайта и AmoCRM. Дашборд: публикация → просмотры → переходы → заявки → деньги.
Риск: средний — у части площадок статистики по API нет.

**Э6. mglass.pro как источник трафика.** Отдельный маршрут: страницы объектов душевых и шторок по той же
схеме; решение — оставаться на Tilda или переносить на свой движок, как сайт зеркал.

**Э7. Маркетинг-директор.** Еженедельный отчёт в Telegram: что вышло, что сработало, план на неделю.
Включается последним: ему нужно 3–4 недели статистики Э5.

## Грабли

- Дословные копии статьи на площадках — дубль: поисковик может поставить копию вместо нашего сайта.
  Сначала индекс у нас (1–2 недели), потом пересказы со ссылкой.
- Частичная выкладка сайта теряет файлы с хешем в имени (шрифты, 19.11) — после выкладки проверять
  все `/_next/` ресурсы страницы.
- В подписях бригадира в «Монтажах» — адреса, телефоны, суммы наличных: на площадки не идут никогда.
- Экран без данных выглядит работающим: проверять таблицы, а не вкладки (контент-план 19.11).

## Потолок

- «Вирусность» не автоматизируется: машина гарантирует регулярность и учёт, а не охват.
- Площадки без API (Дзен, Яндекс Бизнес, 2ГИС — до проверки Э0) — публикует человек по готовому пакету.
- Бесплатный поиск по зеркалам в Москве — сотни, при топ-3 — 1,5–3 тыс. визитов в месяц (COMMERCIAL_ROUTE).
- Нейросети цитируют то, что уже есть в индексе и на площадках; прямого рычага на их ответы нет.
