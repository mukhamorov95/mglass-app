# Замеры: кабинет замерщика и назначение замера — маршрут

Просьба владельца 30.09.2026 (экран «Заявки на замер» + текст, скопированный в Telegram замерщику):
«Давай структуру ровную. И в целом… поработаем по кабинету замерщика. Чтобы было всё понятно, чтобы
легко было назначить менеджеру замер, чтобы замерщик видел все заявки на новый замер и видел все замеры —
когда и где занято. И так же менеджер понимал, когда возможен замер».

## Цель

1. Скопированная заявка читается с одного взгляда: блоки через пустую строку, каждое изделие — своей строкой.
2. Менеджер за один экран видит, когда свободен каждый замерщик, и ставит замер в свободное окно.
3. Замерщик в своём кабинете видит пул новых заявок, свои замеры и общую занятость всех замерщиков.
4. Отпуск/выходной замерщика виден всем и не даёт поставить на него замер.

## Этапы

**З1 — ровное сообщение замерщику — СДЕЛАНО (PR этого этапа).** `lib/measure/message.ts`: сообщение
собирается из полей заявки в момент копирования (все три места создания выглядят одинаково; время и
замерщик — текущие). Блоки через пустую строку, изделия нумерованным списком (разбор «- », «;», строк
и перечисления через запятую перед названием изделия), телефон одной строкой `+7…` (Telegram делает
его ссылкой), «цена не указана» вместо ложного «бесплатно». «Что мерить» в форме — многострочное поле.
Кнопка отвечает «✓ Скопировано». Проверка: `__tests__/measureMessage.test.ts` (заявка 0171-0 дословно).

**З2 — все записи через сервер с правами — СДЕЛАНО (#744, прод 30.09).**
`GET/POST /api/measure-requests` (список по кругу видимости — фильтр в запросе; создание, в т.ч. сразу
с замерщиком и временем), `PATCH /api/measure-requests/[id]` (schedule / unassign / done / issue / cancel /
reopen / fee_paid) с замком по `updated_at` — два замерщика не возьмут одну заявку. Права — `lib/measure/access.ts`
(круги all / measurer / own; выплату отмечает только владелец). Пересечения — `lib/measure/slots.ts`
(жёстко: наложение и отпуск; мягко с вопросом: дорога < 60 мин, вне часов, нерабочий день).
Файл к замеру — только замерщик замера, менеджер заявки, офис, владелец (было — любой вошедший).
Браузерные писатели переведены на API: форма заявок, кабинет, карточка лида CRM. Миграция
`20260930_measure_requests_write_via_api.sql` снимает запись из браузера (только SELECT + revoke).
Проверка: тесты прав и окон. Миграция применена после деплоя; пробы на живой базе 30.09: менеджер
читает 3 заявки (как раньше), `UPDATE … fee_status='paid'` от менеджера — `permission denied`,
аноним — 0 строк. `GET /api/measure-requests` в проде под владельцем — 200, 3 заявки, круг `all`.

**З3 — рабочие часы, выходные и доска занятости — СДЕЛАНО (#745).** Таблицы `measurer_schedules`
(дни недели, с–по; по умолчанию пн–сб 09–20) и `measurer_days_off` (с–по, причина) — миграция
`20260930_measurer_availability.sql` применена; RLS: читают владелец и сам замерщик, запись только сервером.
Пробы 30.09: аноним — `permission denied`, менеджер — 0 из 1, владелец — 1, INSERT менеджера — `permission denied`.
`GET /api/measure-requests/board` — доска на неделю: менеджер у чужих заявок видит время, замерщика и адрес,
без клиента и телефона; причина выходного — владельцу и самому замерщику. `/api/measurers/schedule`,
`/api/measurers/days-off` — правит сам замерщик или владелец; выходной поверх назначенных замеров
сохраняется и называет, сколько замеров перенести. `components/measure/MeasureBoard.tsx` — на
`/measure-calendar`, в «Заявках на замер» («Когда можно на замер») и в кабинете; «ближайшее свободное»
сверху. `MeasurerAvailability.tsx` — «Мой график» в кабинете.

**З4 — менеджер назначает замер в свободное окно — СДЕЛАНО (#747, подтверждения окнами приложения — #749).** В форме заявки блок «Когда
замер»: «🆕 В пул — замерщик сам договорится» или «📅 Уже договорились — назначить сразу» →
`components/measure/BookingPicker.tsx` (замерщик · дата · время · длительность; под ним — что у замерщика
уже стоит в этот день и кнопки «начать можно: 09:00 09:30 …») или клик по зелёному окну на доске ниже.
В списке заявок: «📅 Назначить замерщика» / «↔ Перенести» / «↩ В пул» / «✕ Отменить» / «↺ Вернуть».
Сервер: пересечение и отпуск — отказ; дорога/часы/нерабочий день — `window.confirm` и повтор с force
(`lib/measure/client.ts`). После создания — плашка «где теперь заявка» с кнопкой копирования.
Черновик формы переживает перезагрузку (`localStorage`), «Закрыть» спрашивает.

**З5 — кабинет замерщика — СДЕЛАНО (#747).** `/measurer-cabinet` переписан: счётчики (сегодня /
новых / дальше / не отмечены); «Прошли, но не отмечены»; «Сегодня» — время, клиент, телефон ссылкой,
адрес + «🗺 на карте», что мерить списком, примечание, выезд и гонорар, менеджер, amo; действия ✅ Выполнен,
⚠️ Сложность (форма в карточке вместо prompt), 📎 Файл, ↔ Перенести, ↩ В пул; «🆕 Новые заявки» —
«📅 Взять — выбрать время» в своё окно; «Дальше» по дням; доска всех замерщиков; «Мой график»;
деньги месяца (владельцу — по всем) и история с «💰 Выплачено» (с подтверждением).

**З6 — длительность и дорога при назначении — СДЕЛАНО (PR этапа).** Владелец 01.10: «назначая замер,
он должен прикинуть, сколько займёт сам замер… и если в этот день уже стоит замер — программа должна
сказать: давай поставим, сколько займёт дорога с первого на второй». `BookingPicker`: «Сам замер займёт:
30 мин…3 ч»; если перед выбранным временем в этот день уже стоит замер — «Перед этим у тебя замер 12:00–13:30 ·
адрес. Сколько займёт дорога оттуда? 30 мин / 1 ч / 1,5 ч / 2 ч / свои минуты»; ниже — следующий замер и дорога
до него. Оценка хранится в `measure_requests.travel_min`; окна и проверка считают дорогу до стоящего замера по
его собственной оценке (по умолчанию 60 мин), до нового — по введённой. На доске «🚗 дорога до него N мин».
Часы по умолчанию — пн–пт 09:00–18:00 (суббота — сам замерщик в «Моём графике»). Миграция
`20261001_measure_price_payment_travel.sql` применена до кода (аддитивная).
Проверка удобства (владелец: «потом понять, удобна ли»): через 2 недели живых замеров —
`select count(*) filter (where travel_min is not null and travel_min <> 60), count(*) from measure_requests
where status in ('scheduled','done') and measurer_id is not null` — сколько раз оценку меняли.

## Решения владельца

- **Р1. Завести замерщиков** (Сергей, Глеб) в `/admin/users` с ролью «Замерщик». Без этого доска
  пустая, а назначить можно только «в пул». Разблокирует реальную работу З3–З5.
- **Р2. Часы по умолчанию — РЕШЕНО 01.10:** пн–пт 9–18, суббота по желанию замерщика.
- **Р3. Дорога — РЕШЕНО 01.10:** по умолчанию час, при назначении второго и дальше замера дня замерщик
  оценивает дорогу сам (З6).
- **Р4. Гонорар замерщика для заявок из карточки сделки и лида CRM** сейчас пишется 0 — в деньгах
  замерщика такие замеры будут «0 ₽». Правило: гонорар = цена выезда? Или фиксированная сумма?
- **Р5. Уведомления в Telegram** (новая заявка → группа «Замеры Mglass», назначение → замерщику).
  Не делается без решения: это сообщения живым людям.

## Грабли

- Готовый текст, сохранённый при создании (`structured_text`), стареет в тот же момент, когда заявку
  назначили, и отсутствует у заявок, созданных в обход формы. Сообщение — функция от строки, а не колонка.
- Запятая — не разделитель изделий: «Зеркало 900×2200, от стены до зелёной зоны» — одно изделие.
  Режем по запятой только перед словом-изделием (зеркало, душевая, перегородка, стекло, полка…).
