# Замеры: кабинет замерщика и назначение замера — маршрут

Просьба владельца 30.09.2026 (экран «Заявки на замер» + текст, скопированный в Telegram замерщику):
«Давай структуру ровную. И в целом… поработаем по кабинету замерщика. Чтобы было всё понятно, чтобы
легко было назначить менеджеру замер, чтобы замерщик видел все заявки на новый замер и видел все замеры —
когда и где занято. И так же менеджер понимал, когда возможен замер».

## Цель

1. Скопированная заявка читается с одного взгляда: блоки через пустую строку, каждое изделие — своей строкой.
2. Менеджер за один экран видит, когда свободен каждый замерщик, и ставит замер в свободное окно.
3. Замерщик в своём кабинете видит пул новых заявок, свои замеры и общую занятость всех замерщиков.
4. Отпуск/выходной замерщика виден всем и не даёт поставить на него замер.

## Этапы

**З1 — ровное сообщение замерщику — СДЕЛАНО (PR этого этапа).** `lib/measure/message.ts`: сообщение
собирается из полей заявки в момент копирования (все три места создания выглядят одинаково; время и
замерщик — текущие). Блоки через пустую строку, изделия нумерованным списком (разбор «- », «;», строк
и перечисления через запятую перед названием изделия), телефон одной строкой `+7…` (Telegram делает
его ссылкой), «цена не указана» вместо ложного «бесплатно». «Что мерить» в форме — многострочное поле.
Кнопка отвечает «✓ Скопировано». Проверка: `__tests__/measureMessage.test.ts` (заявка 0171-0 дословно).

**З2 — все записи через сервер с правами — СДЕЛАНО (#744, прод 30.09).**
`GET/POST /api/measure-requests` (список по кругу видимости — фильтр в запросе; создание, в т.ч. сразу
с замерщиком и временем), `PATCH /api/measure-requests/[id]` (schedule / unassign / done / issue / cancel /
reopen / fee_paid) с замком по `updated_at` — два замерщика не возьмут одну заявку. Права — `lib/measure/access.ts`
(круги all / measurer / own; выплату отмечает только владелец). Пересечения — `lib/measure/slots.ts`
(жёстко: наложение и отпуск; мягко с вопросом: дорога < 60 мин, вне часов, нерабочий день).
Файл к замеру — только замерщик замера, менеджер заявки, офис, владелец (было — любой вошедший).
Браузерные писатели переведены на API: форма заявок, кабинет, карточка лида CRM. Миграция
`20260930_measure_requests_write_via_api.sql` снимает запись из браузера (только SELECT + revoke).
Проверка: тесты прав и окон. Миграция применена после деплоя; пробы на живой базе 30.09: менеджер
читает 3 заявки (как раньше), `UPDATE … fee_status='paid'` от менеджера — `permission denied`,
аноним — 0 строк. `GET /api/measure-requests` в проде под владельцем — 200, 3 заявки, круг `all`.

## Грабли

- Готовый текст, сохранённый при создании (`structured_text`), стареет в тот же момент, когда заявку
  назначили, и отсутствует у заявок, созданных в обход формы. Сообщение — функция от строки, а не колонка.
- Запятая — не разделитель изделий: «Зеркало 900×2200, от стены до зелёной зоны» — одно изделие.
  Режем по запятой только перед словом-изделием (зеркало, душевая, перегородка, стекло, полка…).
