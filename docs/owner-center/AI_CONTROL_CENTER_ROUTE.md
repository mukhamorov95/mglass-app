# AI Control Center — маршрут (06.10.2026)

Решение владельца 06.10: «все три этапа по порядку», каждый — отдельный PR.

## Цель

Страница каждое утро отвечает на три вопроса:

1. **Всё ли работает?** Поломка доходит до владельца в Telegram в тот же день, без открытия страницы.
2. **Что ждёт моего решения?** Рекомендации решаются кнопками, в том числе прямо в Telegram.
3. **Что сделать на этой неделе?** Каждая рекомендация опирается на конкретную цифру из названного источника.

Мерило готовности:
- Поломка вида «06.10: кончились деньги на Anthropic» приходит владельцу сообщением с действием.
- Доля решённых рекомендаций больше нуля (на 06.10 — 0 из 9 за три недели).

## Этапы

### 1а. Живые проверки без миграции — СДЕЛАНО (PR этого этапа, 06.10)
- `lib/health/liveChecks.ts` проверяет:
  - Anthropic: пробный запрос на 1 токен; ошибка разбирается на «нет денег», «ключ», «лимит», «сбой у провайдера»;
  - свежесть синка «Аналитики дохода» (`manager_stats_daily.updated_at`);
  - свежесть синка «Маржи» (`margin_book_rows.updated_at`);
  - доступность книги «Монтажи» по ссылке;
  - токен AmoCRM (GET-запрос, только чтение);
  - ошибки очереди Авито → AmoCRM за сутки.
- `GET /api/admin/live-health` отдаёт результат на страницу.
- `/api/cron/live-health` запускается в 09:30 и 14:30 МСК. Если есть красное, отправляет одно сообщение в Telegram со списком и действиями. Пока поломка не устранена, это напоминание дважды в день: без таблицы состояния повторы не отличить.
- Страница:
  - вверху блок «Всё ли работает» вместо счётчиков таблиц;
  - ошибка анализа показывается по-русски и с действием;
  - старые технические проверки свёрнуты;
  - проверки мёртвой таблицы `orders` убраны.
- Риск: пробный запрос к Anthropic стоит доли копейки за вызов и вызывается при каждом открытии страницы и в кроне.

### 1б. Журнал кронов — СДЕЛАНО В КОДЕ, ждёт SQL владельца (06.10)
- Таблица `cron_runs` (`supabase/migrations/20261006_cron_runs.sql`): строка на крон — последний старт, успех, ошибка, длительность. RLS включён, anon/authenticated отозваны; в `SENSITIVE_TABLES`.
- `lib/cronRuns.ts` — обёртка `withCronRun(job, req, run)` и список `CRON_JOBS` с нормой «не реже N часов». Обёрнуты 12 кронов: синки «Продаж», «Аналитики дохода», «Маржи»; сверка реестра, сверка оплат, целостность денег, бэкап, утренняя сводка, распределение заявок, очередь Авито, AI-рекомендации, сама проверка.
  - Ошибка: не 2xx, `ok: false` в ответе или исключение. Вызов без секрета в журнал не пишется.
  - Старт пишется до запуска. Если Vercel оборвал крон по времени, старт окажется новее успеха — это видно.
  - Запись журнала крон не роняет: пока таблицы нет, она просто не ложится.
- «Всё ли работает»: если всё хорошо — одна строка «Кроны: N из 12 проходят». Иначе по строке на каждую беду:
  - упал — красное, с текстом ошибки;
  - успех старше нормы — красное;
  - старт без завершения дольше 15 минут — жёлтое.
  Красное уходит в ту же тревогу Telegram.
- Пока SQL не выполнен, вместо этого жёлтая строка «Журнал кронов не включён» с путём «Supabase → SQL Editor → Run».
- Не обёрнуты остальные ~23 крона (агенты-аналитики, follow-up, SLA и др.). Добавлять по мере правок: одна строка в маршруте и одна в `CRON_JOBS`.

### 2. Решения в Telegram — СДЕЛАНО (06.10)
- `lib/ai/recTelegram.ts`:
  - рекомендация — отдельным сообщением: важность, проблема, что сделать, как проверить;
  - кнопки «🔧 В работу», «📦 Архив», «✖ Убрать»;
  - после решения сообщение переписывается, в нём статус, кто решил и кнопка «↩ Вернуть»;
  - «Сделано» ставится на странице: туда пишется результат.
- Одна функция записи решения `decideRecommendation` для страницы и бота. В `decided_by` бот пишет «почта · Telegram» — видно, откуда пришло решение.
- Бот (`app/api/telegram/webhook/route.ts`):
  - `/recs` или слово «рекомендации» — нерешённые по важности, до 10 штук;
  - решать могут только владельцы (`isOwnerRole`), остальным — отказ.
- Крон рекомендаций:
  - новые приходят каждая со своими кнопками, а не списком заголовков;
  - если копится 8 и больше нерешённых, по понедельникам и четвергам приходит напоминание с кнопкой «Разобрать здесь».
- Мерило: доля решённых больше нуля. На 06.10 — 0 из 9.
