# Прайс душевых — рабочая вкладка (устав)

Отдельный контур работы: **прайсовая система душевых перегородок** (себестоимость → цена клиенту),
которую владелец настраивает по каждой модели М1…М12 на основе прайсов поставщиков.

Ветка: `claude/shower-pricing-system-725ae3`. База: `main` + влит `feat/shower-3d-configurator`
(коммит A2 — избранное/сравнение поставщиков), поэтому здесь самый свежий прайсовый код.

Правило простое: **геометрия даёт количества, прайс даёт деньги.** Контракт между ними —
`Quantities` (`sections`, `glassM2`, `profilePieces[]`, `tubePieces[]`, `hardware{}`, `roles{}`).
Пока контракт не меняется, обе вкладки правятся независимо и мержатся без конфликтов.

## Что уже есть в системе (факт на 2026-08-25)

- Справочник поставщиков `/admin/supplier-catalog`: **Ветро 3261** строк (−32%) + **АВ24 3677** (−25%) = 6938,
  `cost = розница × (1 − скидка)`. Импорт xlsx в браузере, ★ избранное, ⇄ сравнение поставщиков.
- Себестоимость визуализатора `/admin/visualizer-pricing` (тарифы `budget` / `premium`, таблица `configurator_pricing`):
  8 подгрупп по ролям — петли, ручки, ролики, профили, трубы, крепёж, заглушки, уплотнители.
- Движок: `computeQuantities(assembly)` → `computePrice(q, prices)`;
  `Цена изделия = Себестоимость / (1 − маржа 40% − налог 12%)` (канон компании, `calcFinancialModel`),
  сверху монтаж 6500 ₽ × секции + доставка 5000 ₽ + подъём.
- Профиль/труба считаются **хлыстами**: кусок → наименьший хлыст ≥ длины куска.
- Цена считается на сервере (`/api/configurator/quote`): публичному embed уходит только «от N ₽», себестоимость не утекает.

## Главный архитектурный пробел

Цены и состав сегодня **общие на тариф**, а не **на модель**. Движок берёт первую `auto`-позицию
подгруппы, поэтому М2 (распашная) и М10 (раздвижная) собираются одинаковым комплектом.
Владелец хочет настраивать прайс **под каждую модель** — значит нужен слой
**«Комплектация модели»**: для М1…М12 — какая именно позиция играет каждую роль и сколько её штук
(ролики на створку, крепёж на стойку, уплотнители по типу двери). Это следующая крупная задача вкладки.

## Контракт П6 «состав заказа» (согласован до старта, 2026-08-25)

`KitLine` → `public.order_components` (таблица клиентского кабинета, миграция 20260828_order_assembly.sql).
- piece: role→kind (словарь role→kind держит client-cabinet в lib/orderAssembly.ts; я шлю role как есть),
  qty→qty, unitPrice→unit_cost (СЕБЕСТОИМОСТЬ, не цена клиенту), total НЕ переношу (у них GENERATED).
- bar (profile/tube/cap/seal-*): раскладывать на строки ПО ДЛИНЕ хлыста. На каждую длину:
  qty = число хлыстов этой длины (целое), unit_cost = цена ЭТОГО хлыста из справочника (НЕ round(total/n)).
  Данные уже есть: BarResult.bars={длина:кол-во} + цена длины в stocks.
- ВАЖНО: мой KitLine.total для bar — это УЖЕ полная стоимость целых хлыстов (planBars.cost),
  а не доля раскроя. Обрезь уже в себестоимости — доначислять её НЕЛЬЗЯ (будет двойной счёт).
- Стоимость обрези (побочная польза) = Σ(длины куплённых хлыстов) − Σ(длины кусков) в метраже;
  в деньгах — оплаченная часть хлыста, ушедшая в отход. Можно отдавать отдельным полем.
- ROLES стабильны; при добавлении новой роли — пинг client-cabinet (у них CHECK на kind из 7 значений).
Реализуется при сборке корзины (П6), сейчас отложен оркестратором до контракта со складом.

## Открытый риск: себестоимость душевой может быть занижена (замер b2b 25.08)

Замер прода (второй мозг: 01-БИЗНЕС/ОБЩЕЕ/цифры/b2b-факты-из-прода.md) показал по B2B-стеклу:
честная маржа ≈29 %, а не 44,8 % — из-за двух слоёв, которых нет и в моей модели душевых.

1. **Стекло по чистой площади, без отхода раскроя.** У меня glassCost = glassM2(нетто) × ставка.
   Замер: реальный расход листов ≈ВДВОЕ больше чистой площади деталей (обрезь стеллажа в лом).
   Если ставка glassPerM2 НЕ заложена как all-in с отходом — себестоимость стекла занижена.
   NB: раскрой ПРОФИЛЯ/ТРУБЫ у меня точный (целые хлысты), эта претензия к нему НЕ относится —
   только к стеклу, которое я не раскраиваю.
2. **Резка, сверловка — не в себестоимости вообще.** Модель душевой = стекло + фурнитура +
   монтаж + доставка. Нет резки/сверловки (отверстия под петли), и под вопросом кромка/закалка/
   упаковка на изделие. По замеру резка+сверловка ≈310 тыс/мес спрятаны только по B2B.

Следствие: цена клиенту = Себест/(1−маржа−налог) при заниженной Себест → продаём дешевле, чем
думаем. Решение — за владельцем: (а) что именно заложено в ставку glassPerM2 (голое стекло или
all-in), (б) заводить ли строки производственных затрат на изделие (резка/сверловка/кромка/
закалка/упаковка) — как per-операция или % к стеклу. Движок готов принять новые cost-строки;
сам не добавляю без решения — это меняет цену на проде.
