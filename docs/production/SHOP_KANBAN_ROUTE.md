# Табло цеха: заказы по этапам + раскрой для резчика (маршрут 25.11.2026)

**Повод.** Владелец 25.11: табло цеха показывало поручения (Новые / В работе / Готово), а цеху нужно видеть сами заказы, как сделки в amoCRM, — по колонкам этапов. Новые сверху, старые уходят вниз; рабочие берут сверху вниз. Отметили работу по изделию — карточка переехала.

## Цель
Открыв `/production-app/control`, любой в цеху за 5 секунд видит, какие заказы на каком этапе, сколько дней до отгрузки у каждого и из какого материала он. Резчик видит, сколько какого стекла нужно, вводит число целых листов и получает, какие детали и заказы на них резать.

## Этапы

### 1. Канбан заказов по этапам — СДЕЛАНО
* Колонки: Новые → Резка → (Криволинейка) → Полировка → (Сверление, Фацет, Песочка) → Закалка → (Триплекс) → Упаковка → Упакован → Отгружен (последние 7 дней). Редкие этапы показываются, только если в них есть заказы.
* Заказ стоит в колонке **самого раннего этапа, где у него есть незакрытая деталь**: одна деталь не нарезана — заказ ещё на «Резке». «Новые» — ни одной отметки.
* Карточка: №, заказчик, дата запуска, дата отгрузки, изделий (шт.), операций сделано из всех, крупно — дней до отгрузки (красное — просрочка), материалы: стекло и зеркало отдельными строками с толщиной и штуками.
* Поиск по номеру, заказчику, материалу. Порядок в колонке — запуск, новые сверху.
* Поручения не убраны: кнопка «📌 Поручения» (`?view=tasks`); уведомления и лента поручений ведут туда.
* Данные — тот же `/api/production/orders-board`, что у «Заказов» (одна функция, одно окно); добавлены `column`, `materials`, `ops_done/ops_total`.
* Проверка: тест `__tests__/production/stageKanban.test.ts`, кадр на проде.

### 2. Режим резчика: материал по группам — ДАЛЬШЕ
* Над колонками «Новые» и «Резка» — блок «Нужно нарезать»: группы «вид + название + толщина», в каждой — деталей, м² и заказов (только детали с незакрытой резкой).
* Риск: в старых позициях нет materialId — группировка по названию и толщине.

### 3. Раскладка на N листов по очереди запуска — ДАЛЬШЕ
* Резчик нажимает группу, вводит, сколько целых листов есть (1, 3…). Детали берутся заказами по дате запуска (раньше запущен — раньше режется); заказ добавляется, пока помещается на N листов (`runCuttingOptimizer` из `lib/cuttingOptimizer.ts`, формат листа — из справочника материала). Итог: какие заказы/детали на какой лист, что не влезло.
* Риск: формат листа у материала может быть не задан — тогда спросить размер листа в той же форме.
* Решение владельца, которое нужно: заказ, который влезает только частично, — резать частью или переносить целиком? По умолчанию — целиком переносим (не разрываем заказ).

## Грабли
* Сортировка «новые сверху» взята дословно. Раскладка на листы (этап 3) — наоборот, первыми старые по запуску. Если в колонках тоже нужны старые сверху — одна строка в `kanbanSort`.

## Потолок
Колонка показывает отметки цеха. Если этап не отмечают, заказ стоит на нём, даже если стекло уже дальше (на 25.11 открыто 194 резки и 294 упаковки).
