# Order Management Skill — Навык управления заказами

## Назначение
Полный жизненный цикл заказа: создание из расчёта → статусная воронка → контроль маржи → оплата → производство → доставка → завершение. Центральный Skill бизнеса — без него нет продаж.

## Модули и страницы
- `/orders` — список заказов с фильтрами по статусу/менеджеру
- `/orders/[id]` — детальный заказ: позиции, оплата, история изменений
- `/orders/[id]/print` — печать заказа
- `/orders/[id]/act` — акт выполненных работ
- `/orders/[id]/spec` — спецификация
- `/production` — производственный список (для бригад)
- `/manager-dashboard` — дашборд менеджера: свои заказы, KPI

## API маршруты
- `POST /api/orders` — создать заказ из расчёта (одного или корзины)
- `PATCH /api/orders/[id]/status` — изменить статус заказа
- `POST /api/orders/[id]/approve` — одобрить заказ (admin only)
- `PATCH /api/orders/[id]/payment` — обновить оплату (тип + суммы)
- `PATCH /api/orders/[id]/delivery` — назначить зону доставки
- `PATCH /api/orders/[id]/brigade` — назначить монтажную бригаду
- `POST /api/orders/[id]/photos` — загрузить фото выполненных работ
- `POST /api/orders/[id]/rating` — оценка клиента (1–5)
- `POST /api/orders/[id]/custom-number` — задать кастомный номер
- `PATCH /api/orders/[id]/production-stages` — этапы производства
- `GET /api/orders/production` — список заказов для производства

## Роли и доступ
- **manager**: создаёт заказы, видит только свои, не может одобрять
- **production**: видит все заказы, меняет статусы производства, этапы
- **buyer**: видит для логистики и закупок
- **admin/ceo**: видит всё, одобряет, может редактировать любое поле

## Входные данные
Один расчёт или корзина расчётов (calculation_id[]), данные клиента (имя, телефон, адрес), дедлайн, AMO-ссылка, финансовые настройки.

## Выходные данные
Заказ с уникальным номером, BOM-список позиций, печатные документы (акт, спецификация), уведомления команде.

## Что уже реализовано
- Создание заказа из корзины расчётов (`LaunchOrderModal`)
- Статусная воронка: draft → pending_approval → approved → in_work → completed/cancelled
- Контроль маржи: при марже ниже порога → статус `pending_approval` + уведомление admin
- Оплата: unpaid/partial/paid + суммы (paid_amount, remaining)
- История изменений расчёта через `calculation_changes`
- Производственный список для бригад
- Фото выполненных работ (Supabase Storage)
- Акт и спецификация (печатные страницы)

## Что нужно доработать
- Мульти-позиционные заказы в полном объёме (сейчас частично через корзину)
- Интеграция с производством: этапы нарезка → монтаж → доставка с датами
- SLA-трекинг: cron уже есть (`/api/cron/`), но страница не показывает просрочку
- Автоматическая стоимость доставки по зоне при создании заказа

## Риски
- Одобрение — только admin. Если admin недоступен, заказ застревает в `pending_approval`
- `lib/notify.ts` использует Resend — молча не работает если `RESEND_API_KEY` не задан
- Удаление бригады оставит `brigade_id` в заказах (нет CASCADE → NULL)
- Нет блокировки одновременного редактирования заказа двумя пользователями

## Тесты
- Integration: создание заказа с маржой ниже порога → статус `pending_approval` + уведомление
- Integration: одобрение admin → статус `in_work` + уведомление менеджеру
- E2E: менеджер создаёт заказ из расчёта → admin одобряет → статус меняется
- Smoke: производственный список рендерится для роли `production`

## Связи с другими Skills
- **Calculation Skill** — источник: заказ создаётся из одного или нескольких расчётов
- **Commercial Proposal Skill** — КП становится заказом после одобрения
- **Logistics Skill** — назначение зоны доставки и бригады к заказу
- **CEO Analytics Skill** — потребляет данные заказов для P&L и дашборда
