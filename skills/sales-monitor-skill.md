# Skill: Sales Monitor — Ежедневный контроль отдела продаж

## Назначение

Автоматический ежедневный разбор работы каждого менеджера по данным AmoCRM.
Запускается в 18:00, только READ-запросы к API — **никаких следов в карточках** (никаких примечаний, задач, звонков, webhooks в сделки).
Отправляет отчёт руководителю в Telegram.

## Менеджеры

| Имя       | Роль в AmoCRM     |
|-----------|-------------------|
| Алина     | responsible_user  |
| Семён     | responsible_user  |
| Александра| responsible_user  |
| Яна       | responsible_user  |

## Данные из AmoCRM API (только GET)

### Endpoint-ы (все — read-only)

```
GET /api/v4/leads          — сделки (фильтры: modified_from, responsible_user_id)
GET /api/v4/events         — события (тип: deal_status_changed, message_sent, call)
GET /api/v4/contacts       — контакты
GET /api/v4/users          — список менеджеров с ID
GET /api/v4/pipelines      — воронки и этапы
```

### Метрики по каждому менеджеру (за текущий день, 00:00–18:00)

| Метрика                        | Источник                                      |
|-------------------------------|-----------------------------------------------|
| Заявок получено               | leads created_at = сегодня                    |
| Сообщений написано клиентам   | events type=message_sent, created_by=user     |
| Звонков сделано               | events type=call (outgoing), created_by=user  |
| Карточек перемещено           | events type=lead_status_changed, by=user      |
| Активных сделок на 18:00      | leads status≠closed, responsible=user         |

### Распределение сделок по зонам воронки

**Зона 1 — Квалификация (верх воронки)**
`"Назначен ответственный"` → `"Готов купить"`

Что мониторим: скорость движения, длина пребывания, зависшие без активности >2 дней.

**Зона 2 — Активная продажа (середина)**
`"Замер назначен"` → `"Счёт выставлен - ждем оплату"`

Что мониторим: конверсия замер→счёт, сделки без движения >3 дней.

**Зона 3 — Производство/Оплата (нижняя)**
`"Оплата сделана, чертежи не готовы"` → `"Оплата остатка"`

Что мониторим: блокеры производства, просроченные остатки.

## Аналитика: взгляд Руководителя отдела продаж

Система не просто считает цифры — она интерпретирует их как РОП:

### Красные флаги (срочно)
- Менеджер сделал 0 исходящих сообщений/звонков за день
- Сделка в Зоне 1 без касания >2 дней → риск потери лида
- Сделка в Зоне 2 без движения >3 дней → риск отказа после замера
- Счёт выставлен >5 дней — клиент не платит, нет контакта
- Менеджер получил много лидов, но почти не двигал карточки

### Жёлтые флаги (обратить внимание)
- Менеджер активен по сообщениям, но мало звонков (или наоборот)
- Диспропорция: у одного менеджера активных сделок значительно больше, чем у других
- Сделки накапливаются в одном этапе у конкретного менеджера
- Конверсия "замер назначен" → "счёт выставлен" ниже средней по команде

### Зелёные сигналы (отметить)
- Менеджер перемещает сделки быстро + коммуникация высокая
- Нет зависших сделок в зоне 1 и 2
- Счёт оплачен быстро после выставления

## Реализация (технический план)

### Файлы

```
lib/amocrm.ts                          — клиент AmoCRM API (token refresh, rate limit)
lib/salesMonitor.ts                    — логика сбора и анализа данных
app/api/cron/sales-monitor/route.ts    — cron-endpoint (POST, защищён CRON_SECRET)
```

### Расписание

```
vercel.json или cron-задача:
"0 15 * * *"  — каждый день в 18:00 МСК (UTC+3 → 15:00 UTC)
```

### ENV переменные

```
AMOCRM_DOMAIN=yourdomain.amocrm.ru
AMOCRM_CLIENT_ID=...
AMOCRM_CLIENT_SECRET=...
AMOCRM_REFRESH_TOKEN=...          # обновляется автоматически
TELEGRAM_BOT_TOKEN=...
TELEGRAM_CHAT_ID=...              # ID чата руководителя
CRON_SECRET=...                   # защита endpoint-а
```

### Принципы READ-ONLY (никаких следов)

```typescript
// ✅ Разрешено
GET /api/v4/leads
GET /api/v4/events
GET /api/v4/users

// ❌ Запрещено (оставляет след)
POST /api/v4/leads/{id}/notes
PATCH /api/v4/leads/{id}
POST /api/v4/tasks
```

Токен AmoCRM используется только для чтения. Scope: `crm`.

## Риски

| Риск                              | Митигация                              |
|----------------------------------|----------------------------------------|
| Истёк refresh_token AmoCRM       | Автообновление + алерт в Telegram      |
| AmoCRM API rate limit (7 req/s)  | Throttling, задержки между запросами   |
| Менеджеры удалены/переименованы  | Сопоставление по user ID, не имени     |
| Cron не запустился               | Health-check пинг после выполнения     |
